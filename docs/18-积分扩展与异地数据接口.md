# 18 积分扩展、异地同步与接口开关（v5）

所有路径和字段是本项目待实现契约，不宣称现成Emby/Twilight自带这些接口。默认关闭外部积分写入和远端数据接口；本机签到、账本、正常备份不依赖它们开启。

## 1. 面向群内小游戏的积分事件

预留来源适配器`GAME_REWARD`，不把游戏逻辑、群消息解析和钱包写入混在同一事务。未来群Bot在允许的群内运行免费互动游戏，验证获奖事实后由服务端提交奖励事件；用户发一条“我赢了”或小游戏前端回传分数不能直接入账。

首期只是接口和表结构，不启用游戏。默认不支持现金下注、购买抽奖次数、积分提现、用户转账、付费随机奖励；未来新增活动时另明确规则、预算和审核，不顺带改变签到概率模型。

```json
{
  "event_id": "demo-event-unique",
  "source_id": "demo-game-server",
  "event_type": "GAME_REWARD",
  "telegram_user_id": "123456789",
  "group_id": "-1000000000000",
  "game_id": "demo-quiz",
  "round_id": "demo-round",
  "occurred_at": "2026-11-13T08:00:00Z",
  "rule_version": "quiz-v1",
  "proposed_points": 5,
  "evidence_ref": "round-result-reference"
}
```

服务端验证source身份、scope、允许群/游戏、UID映射、规则版本、获奖事实、时效、单局唯一及限额。`proposed_points`只作申请，实际值由服务端已发布活动规则决定，客户端不能指定任意用户、积分或活动通过。TG ID使用64位或十进制字符串，不能使用会丢精度的前端数字；没有已有成员映射则拒绝或进入待认领，默认不自动注册/建第二钱包。

外部游戏奖励默认只影响可用钱包，**不算签到活动分、不算观影、不解除封禁、不自动续期**。中奖、日常签到、管理员调整、卡码、邀请等来源在账本中独立标记。月卡测算仍是仅正常签到的基线，开启游戏后UI另列活动收益，不把游戏收入默认为人人可得。

## 2. API与签名契约

| 接口 | scope与语义 |
|---|---|
| `POST /v1/integrations/points/events` | `points:event:submit`，申请事件，不是直接设余额 |
| `GET /v1/integrations/points/events/{event_id}` | 仅本source状态/脱敏结果，不读任意用户余额 |
| `POST /v1/admin/integrations/{id}/disable` | Owner紧急关闭/撤销版本，独立审计 |
| `POST /v1/admin/points/events/{id}/reverse` | 财务/Owner冲正，引用原账本，不删原事件 |

每来源独立密钥/服务身份，只授事件写入；不复用Bot Token、Emby管理员Key或备份下载Token。首期可选mTLS叠加HMAC：签名串固定为`key_id\ntimestamp\nnonce\nMETHOD\ncanonical_path\nbody_sha256`（分隔符是LF，无额外空格）；canonical_path取固定路由绝对路径、不含query，拒绝控制字符/非规范编码，实现时提供固定测试向量。带时间戳、随机nonce与幂等键，服务端校验原始字节、常量时间比较、默认±300秒、nonce至少留10分钟。时钟不准拒绝并提示校时，不扩大到无限窗口。

签名防重放与业务幂等是两层：重试用新时间戳/nonce、相同event_id。唯一(source_id,event_id)及(source_id,game_id,round_id,user_id,reward_kind)保证换event_id也不能刷同一奖励；同ID不同payload返回409。方法/路径、Content-Type和body尺寸受限，不能靠URL查询串传密钥或秘密。

每来源设每事件/每UID每日/每群每日/来源每日/全服每日上限、速率、规则有效期与预算；超过时不发部分奖励，返回明确限额或人工审核。起始建议单事件≤20分、每人游戏日≤30分、来源日≤500分，仅是将来启用时的预算提案，默认开关false不发一分。预算检查、事件、账本和outbox同事务；并发超过最后1分只接受可完整满足的一笔。

日预算默认与签到同用北京时间，按实际入账日扣预算；occurred_at不允许客户端倒填日期换新额度，默认超过24小时事件入人工审核而非直接发奖。每UID游戏日预算跨source聚合，不能加第二来源就翻倍；全局/来源/用户锁按固定顺序获取，防预算并发穿透和死锁。密钥轮换绑定key_id及来源epoch，旧key撤销后重试需新授权但仍保留原event_id。

队列状态RECEIVED/VALIDATED/APPROVED/APPLIED/REJECTED/HELD/REVERSED。202只代表收到，查询返回实际到账流水；只有APPLIED才提示已获积分。欺诈冲正不改历史奖额；已消费不足时先冻结相关账户的进一步奖励/消费并人工处理，不默默扣成负数或物理删用户。

## 3. 手动关闭的准确含义

开关层级：全局external_points、source、具体game/group、key、scope。后台显示期望版本、已执行版本、最近请求、已拒绝数量和在途任务。关闭动作提交时提升`integration_epoch`；执行写入前再次核对数据库当前开关/epoch，不能只在网关验一次、队列几小时后照样发。

开关事务与最终账本提交在同一来源控制锁/一致性边界排序：关闭确认之前已提交的不回滚；确认之后不再有旧授权入账。已接收未应用标HELD/REJECTED_DISABLED，重新开启不自动补发，需要Owner按新策略预览重放。关闭回调不关闭本机签到/管理员受控调整；两类权限独立。

紧急撤销不只隐藏页面或删定时任务；同时撤source key、短令牌/缓存epoch、在途写入能力，保留审计。查询/健康可单独开关，来源只能看到自己的事件；错误码区分403权限、409幂等冲突、422规则、429预算、503维护，不返回数据库堆栈。[OWASP REST安全](https://cheatsheetseries.owasp.org/cheatsheets/REST_Security_Cheat_Sheet.html)

## 4. 外端VPS备份方式

默认**主站向专用备份VPS推送加密快照**，不开放生产数据库端口，也不把备机接成可写用户中心。可选备机拉取受限备份包；push、pull分别有独立开关/授权。连续实时只读数据流作为未来扩展，不把“同步”写成已实现零丢失热备。

| 模式 | 数据与风险边界 |
|---|---|
| 加密文件快照推送（推荐） | 一致性DB备份、必要配置、manifest；备端无解密私钥，不需要生产数据库密码 |
| 受限快照拉取 | 备机专用只读身份只列manifest、按ID下载；不能传任意路径/SQL |
| 增量事件导出（后续） | 账本/订单/卡码核销等追加事件，按水位+hash链校验；需快照和完整回放验证 |
| PostgreSQL物理复制（另案） | 要求版本/网络/WAL/磁盘与恢复经验；不等于现有HTTP接口功能 |

默认推送每小时业务快照（启用真实交易时），每日完整范围；两端版本和schema登记，CPU压缩并发1、带宽/空间/包大小上限可调。当前2GB先评估实际备份峰值；复制频率、RPO/RTO是目标，未演练不保证。

## 5. 备份API最小集合

| 接口 | 能力 |
|---|---|
| `GET /v1/backup/manifests?after=cursor` | 只列该备份身份允许范围的完成快照，分页 |
| `GET /v1/backup/exports/{export_id}/chunks/{chunk}` | 已完成包的固定分片，可断点续传，身份绑定 |
| `POST /v1/backup/receipts` | 备机确认所收export/文件hash/尺寸/水位；不触发生产恢复或删除 |
| `POST /v1/admin/backup-destinations/{id}/test` | Owner受限连接测试，无任意URL/命令执行 |
| `POST /v1/admin/backup-exports` | 创建固定范围一致性任务，Owner/受限计划器可用 |

列表scope、下载scope、创建scope、接收确认scope分开。备机不能拥有生产恢复、用户修改、积分写入、支付确认、发码、下载secrets等权限。远端目标固定域名/端口/证书或SSH主机指纹；更改地址需MFA、连通测试、影响预览，防把全库发到攻击者地址。

每包至少记录source_instance_id、dataset、snapshot_id、schema/version、created_at、consistent_at、ledger/event高水位、行数/控制总额、每文件长度/hash、加密/签名key_id。加密包完整收齐、验hash与来源签名后才原子标COMMITTED，未完成part不作成功备份；hash不替代签名或认证加密。

重传相同snapshot_id+hash幂等；同ID不同hash拒绝隔离。只有备机独立回执且能定期抽样解密恢复后，面板才分别显示“已复制”和“恢复已验证”；TCP发送成功不是备份完成。备机磁盘满/慢速/离线报警，禁止反过来删生产数据给它腾空间。

保留7日/4周/3月可调，生产推送身份只有写新包权限，不能删备机历史；清理由备端独立权限/保留任务负责。对重要账本启用备端不可变/离线轮换，避免主机被入侵后加密备份一起被覆盖。主站同步的删除事件不能自动删除全部历史快照。

## 6. 数据最小化与停用

备份profile分BUSINESS_RECOVERY、MEDIA_CONFIG、USER_EXPORT，scope绑定profile，不给泛用“导出全部表”。业务恢复需要身份/账本/订单/卡码HMAC及核销/撤销/权益/规则；包含个人数据时整包加密。会话、一次性重置票据、可支取红包口令、未脱敏截图不进入常规异地包。交付码密文按单独敏感profile决定；不带则恢复后走旧码撤销＋重发的受控流程，不能凭哈希重建原码。

备份私钥/解密材料与包分开保存；备机持有可解密资料就仍有泄露风险，不宣传“在异地天然安全”。密钥轮换保留恢复旧包能力，撤销仅网络访问不等于旧包不可解密。

全局/目标push/pull接口可手动关闭并撤令牌；关闭确认后拒绝新请求、停调度、取消在途应用传输/下载响应并让旧下载票据失效。已经交给网络/对端的字节无法收回，关闭不删除对端已收备份。可另留本地离线备份，UI显示异地保护已停、当前RPO增长，不能继续绿色“备份正常”。

接口关闭不等于停止本地业务写入；若要迁移切换，需第11篇停写、最终水位和单主接管。远端不得仅凭心跳超时自动接管发码/扣分/Bot，先隔离旧主、对账最新收款/码核销与epoch再接管，避免双主。

## 7. 恢复时特别防止的回退

已消费兑换码、恢复码、退款撤销、积分冲正、接口停用/密钥撤销、安全封禁需要独立可信追加记录和最新epoch。恢复快照若落后这些事实，先阻断核销、核款、外部积分、交易和通知，补齐后再开放；无法确认的未兑销售码先冻结/人工对账，不批量重发。人工收款账单没有自动重放回调，必须保存独立核款引用与对账记录，否则1小时备份间隔仍可能漏最后一笔。

验收必须覆盖重放、换event_id刷同局、伪造TG ID、最后预算并发、关闭瞬间在途入账、备机越权、任意导出路径、传输中断/错hash/满盘、旧包恢复复活已用码、主机与备机同时收件。上述是实施测试项，本轮仅审查契约。
