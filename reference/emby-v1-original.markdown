\# 纯网盘 Emby 媒体服务完整实施方案



> 版本：1.0

> 规划范围：纯网盘媒体服务（Cloud Emby）

> 目标用户：以中国大陆用户为主，同时兼容海外网盘

> 核心架构：网盘存储 + STRM 媒体索引 + Emby 媒体服务 + 直链/302 播放 + Telegram 机器人 + 用户订阅管理

> 设计原则：媒体文件尽量由网盘/CDN直接交付，VPS只负责媒体库、索引、用户管理、自动化和控制逻辑。



\---



\# 一、项目目标与最终效果



\## 1.1 建设目标



搭建一套独立运行的网盘型 Emby 服务，用户通过 Emby 客户端访问影视媒体库。



系统需要实现：



\- 支持多个网盘账号。

\- 支持国内网盘和海外网盘。

\- 支持多个网盘同时组成一个媒体库。

\- 支持电影、电视剧、动漫、纪录片、综艺等分类。

\- 自动同步网盘目录，生成 STRM 文件。

\- 自动识别影片名称、年份、季数、集数。

\- 自动获取海报、简介、演员、评分等元数据。

\- 支持新剧追更和自动入库。

\- 支持字幕、NFO、海报等辅助文件同步。

\- 尽可能让视频通过网盘直链或 302/CDN 播放。

\- 支持多个 Telegram 机器人管理不同业务。

\- 支持用户注册、购买、支付、续期、保号。

\- 支持设备绑定、设备数量限制、同时播放限制。

\- 支持求片、入库通知、到期提醒、故障通知。

\- 支持网盘账号异常、Cookie失效、STRM失效、媒体缺失等监控。

\- 支持备份、恢复、迁移和故障处理。



\## 1.2 最终用户体验



用户购买套餐后：



1\. 在 Telegram 机器人注册账号。

2\. 选择套餐并完成支付。

3\. 系统自动创建 Emby 用户。

4\. 用户获得 Emby 服务器地址、账号和密码。

5\. 使用 Emby 客户端登录。

6\. 浏览电影、电视剧、动漫等媒体库。

7\. 选择影片后开始播放。

8\. 如果资源支持直链，播放请求由 Emby 或直链服务完成鉴权后跳转到网盘/CDN。

9\. 用户可以在 Telegram 查询套餐、设备、同播状态、求片进度和续费信息。



理想情况下，VPS不负责传输整部视频，只处理媒体库信息、鉴权、索引和管理请求。



\## 1.3 必须明确的三个概念



| 能力     | 实际含义                         | 是否代表可以302   |

| ------ | ---------------------------- | ----------- |

| 网盘挂载   | 能够浏览和读取网盘目录                  | 否           |

| STRM生成 | 把网盘文件映射成Emby可识别的本地文本入口       | 否           |

| 直链/302 | 播放时返回网盘文件的有效播放地址，让客户端直接访问文件源 | 是，但需要具体实现支持 |



不要因为某个网盘能在 OpenList 中正常浏览，就认定它可以在 Emby 中无损直链播放。

\## 2.3 为什么采用国外 VPS



国外 VPS 可以作为媒体管理和索引节点，但并不代表所有海外网盘都适合中国大陆用户直接播放。



需要把两个链路分开看：



\*\*控制链路：\*\*



```text

中国用户 → Emby VPS → 媒体库、登录、用户管理

```



\*\*媒体链路：\*\*



```text

中国用户 → 网盘/CDN → 视频文件

```



理想情况下，视频不经过 VPS。



但如果网盘不支持 302，或者客户端必须通过 VPS 代理读取视频，那么视频流量仍会经过 VPS。此时 VPS 的带宽、流量、线路和出口位置都会影响播放。

\# 三、VPS硬件与线路规划



\## 3.1 当前已有 VPS



现有配置：



\- CPU：2核

\- 内存：2GB

\- 硬盘：30GB

\- 线路：非优化线路

\- 位置：国外



这台机器可以用于：



\- 部署测试环境。

\- 测试 Emby。

\- 测试 OpenStrm。

\- 测试网盘驱动。

\- 测试 STRM 生成。

\- 测试 Telegram Bot。

\- 测试用户管理和自动化任务。



不建议在未验证性能和线路之前，直接把它作为正式运营节点。



\## 3.2 正式推荐配置



| 配置  |         起步推荐 |         更稳妥的配置 |

| --- | -----------: | -------------: |

| CPU |           4核 |           4-8核 |

| 内存  |          8GB |           16GB |

| 系统盘 |    80GB NVMe | 100-160GB NVMe |

| 网络  |  1Gbps共享口需实测 |       1Gbps及以上 |

| 流量  |     按实际使用量核算 |    优先选择流量充足的方案 |

| 系统  | Debian 12/13 |   Debian 12/13 |



建议正式环境使用 \*\*4C8G、100GB NVMe\*\* 起步。



如果只是 Emby + OpenStrm + 少量网盘同步，4C8G通常足够作为初期配置。大量网盘账号、频繁目录扫描、复杂媒体刮削和多机器人任务会增加内存与CPU需求。



\## 3.3 VPS线路到底需不需要优化



需要区分管理流量和播放流量。



\### 情况A：所有影片都能直链播放



```text

用户 → VPS：登录、加载海报、获取媒体信息

用户 → 网盘CDN：下载视频

```



这种情况下：



\- VPS不需要承担视频大流量。

\- VPS线路主要影响登录、媒体库加载和接口响应。

\- 不一定需要高价优化线路。

\- 重点关注中国大陆访问稳定性、丢包、晚高峰延迟和跨境连接稳定性。



\### 情况B：部分网盘需要经过VPS代理



```text

用户 → VPS → 网盘 → VPS → 用户

```



这种情况下：



\- VPS会产生大量出入站流量。

\- VPS线路质量直接影响播放。

\- 需要考虑带宽、流量、回源速度、CPU和连接数。

\- 普通小流量套餐可能很快不够用。



\### 情况C：海外网盘在中国大陆访问不稳定



即使网盘支持直链，也不代表中国大陆网络能够稳定访问。



可能出现：



\- 网盘域名无法正常解析。

\- 登录或鉴权接口不可达。

\- 播放域名连接不稳定。

\- 跨境链路丢包。

\- 下载速度波动。

\- 播放中途连接断开。



因此，海外网盘必须使用中国大陆网络环境进行实际播放测试。



\## 3.4 线路选择建议



| 用途           | 线路优先级            |

| ------------ | ---------------- |

| Emby管理页面     | 稳定、低丢包           |

| OpenStrm网盘同步 | VPS到网盘API稳定      |

| 海外网盘接口       | VPS到目标网盘连接稳定     |

| 中国用户登录       | 中国大陆访问VPS稳定      |

| 视频直链播放       | 用户到网盘/CDN稳定      |

| 视频代理播放       | 用户到VPS、VPS到网盘均稳定 |



\*\*结论：初期不建议为了 Emby 直接购买昂贵的优化线路。\*\*



先把 2C2G VPS 用作测试环境，测试完成后再决定是否升级。真正需要优化的链路取决于最终选用的网盘及播放方式。

\# 四、网盘选型与多网盘接入



这是整套系统最重要的部分。



不能只看容量和价格，还必须看：



1\. 是否允许长期保存和播放目标内容。

2\. 是否有稳定的文件访问接口。

3\. 是否支持 Range 请求。

4\. 是否支持大文件下载。

5\. 是否支持稳定的直链。

6\. 直链是否有有效期。

7\. 是否需要 Cookie 或特定请求头。

8\. 是否限制并发和请求频率。

9\. 是否限制外部播放器使用。

10\. 中国大陆用户能否稳定访问。

11\. 是否有 API 限额或账号风控。

12\. 是否允许当前使用方式及相应商业用途。

\### 重点：115网盘



建议把115作为国内网盘的优先测试对象。



OpenStrm当前公开项目说明中包含：



\- 115目录同步。

\- STRM文件生成。

\- Emby 302直链。

\- 网盘目录监控。

\- 新资源增量同步。

\- 分享转存。

\- 自动追更。

\- 云下载任务。

\- Telegram通知与遥控。

\- STRM文件检查和修复。

\- 影片规范化整理。



它适合承担纯网盘服中的主力存储角色。



需要注意：



\- 115账号有自身的接口限制和风控机制。

\- 不能无限提高同步频率。

\- 不能把接口并发能力直接等同于视频播放并发能力。

\- Cookie、授权和播放链接失效都需要监控。

\- 正式使用前需要核对网盘账号类型、服务条款和使用权限。



参考项目：



\- OpenStrm：\[https://github.com/indown/openStrm](https://github.com/indown/openStrm)



\### 重点：夸克网盘



OpenStrm目前支持夸克网盘目录同步、STRM生成、分享转存、追更等能力。



但是其项目文档明确指出：夸克直链获取需要携带Cookie，因此不支持当前实现下的302播放。



这意味着：



\- 可以将夸克作为资源存储来源。

\- 可以生成STRM。

\- 但不能默认认为Emby可以将视频直接302给客户端。

\- 如果播放需要通过代理层读取视频，就要核算VPS流量和带宽。



因此，夸克更适合作为辅助存储，而不是未经测试就作为主要直链播放源。



\## 4.2 海外网盘候选



海外网盘可以接入，但必须把“文件管理能力”和“视频播放能力”分开评估。



| 海外存储          | 接入方式              | 主要用途       | 需要重点测试          |

| ------------- | ----------------- | ---------- | --------------- |

| Google Drive  | rclone / OpenList | 大容量文件存储、同步 | 中国大陆访问、API限额、直链 |

| OneDrive      | rclone / OpenList | 文件存储和同步    | 访问稳定性、下载限制、鉴权   |

| Dropbox       | rclone / OpenList | 文件存储、同步    | 下载接口、带宽及流量规则    |

| MEGA          | rclone / OpenList | 文件存储       | 下载限额、客户端兼容      |

| PikPak        | OpenList等接入层      | 个人网盘资源管理   | 驱动能力、访问限制       |

| Yandex Disk   | rclone / OpenList | 海外存储       | 中国大陆访问、直链稳定性    |

| pCloud        | rclone            | 海外文件存储     | 下载接口和流量政策       |

| Backblaze B2  | S3兼容接口 / rclone   | 对象存储       | 下载费用、请求费用、出口费用  |

| Cloudflare R2 | S3兼容接口 / rclone   | 对象存储       | 访问策略、出口和请求费用    |

| Wasabi        | S3兼容接口 / rclone   | 对象存储       | 最低存储周期、请求和下载政策  |

| Amazon S3     | S3接口 / rclone     | 正式对象存储     | 存储、请求和出网费用      |



海外网盘与对象存储不是完全相同的产品：



\- Google Drive、OneDrive、Dropbox属于文件同步/个人云盘类型。

\- S3、B2、R2、Wasabi属于对象存储类型。

\- 对象存储通常更适合程序化管理、标准API和长期服务架构。

\- 个人网盘可能存在更严格的下载限制、API政策和账号使用约束。



如果未来服务规模较大，不建议只依赖个人网盘账号。应优先评估具有明确服务条款、可预测费用和稳定API的对象存储。



\## 4.3 海外网盘的接入工具



\### OpenList



项目地址：



\[https://github.com/OpenListTeam/OpenList](https://github.com/OpenListTeam/OpenList)



OpenList可作为统一网盘接入层。



其生态文档列出了国内网盘、海外网盘、S3对象存储、WebDAV、FTP、SFTP等多类存储驱动。



适合：



\- 统一管理多个网盘。

\- 统一浏览目录。

\- 统一提供文件访问入口。

\- 将不同网盘纳入统一目录结构。



但要注意：



\*\*OpenList支持某个网盘，不等于Emby一定能通过302直接播放这个网盘。\*\*



OpenList解决的是存储接入和文件访问问题，真正播放还要验证直链、Range、鉴权和客户端兼容性。



\### CloudDrive2



适合将更多网盘映射为本地文件系统。

适用场景：

\- 需要将网盘映射为统一目录。

\- 希望用统一文件系统方式进行扫描和管理。



但它并不能自动解决所有网盘的直链问题。

rclone支持大量云存储后端，包括：

\## 4.4 网盘接入能力分级



建议给每个网盘建立能力档案，而不是只登记一个网盘名称。



| 等级 | 能力                        | 推荐用途          |

| -- | ------------------------- | ------------- |

| A级 | STRM + 302 + Range + 稳定鉴权 | 主力播放网盘        |

| B级 | STRM + 直链，但需要特定鉴权         | 经过测试后用于播放     |

| C级 | STRM + 服务端代理读取            | 辅助存储，需核算VPS带宽 |

| D级 | 只能挂载或同步，播放链路不稳定           | 备份或冷存储        |



建议正式上线前至少完成以下测试：



\- 1080P连续播放30分钟。

\- 4K连续播放30分钟。

\- 拖动进度条。

\- 快进、快退。

\- 播放字幕。

\- 播放多音轨。

\- 多用户同时播放。

\- 播放中途断网恢复。

\- Cookie或授权过期后的恢复。

\- 网盘直链过期后的重新获取。

\- 客户端在不同网络下的兼容性。



测试结果记录到数据库，作为是否允许该网盘进入正式媒体库的依据。

\# 五、推荐的网盘组合方案



不建议一开始就购买五六种网盘。先把一套主力存储跑稳定，再逐步增加其他来源。



\## 5.1 推荐组合A：国内网盘为主



| 角色     | 方案                 |

| ------ | ------------------ |

| 主力网盘   | 115                |

| 辅助网盘   | 夸克                 |

| 网盘聚合   | OpenList           |

| STRM管理 | OpenStrm           |

| 同步和备份  | rclone             |

| 播放方式   | 115优先302，其他按实际能力决定 |



优点：



\- 面向中国大陆用户。

\- 国内网盘访问路径更容易测试。

\- 115有明确的OpenStrm 302实现。

\- 可以逐步扩展其他网盘。



缺点：



\- 不同网盘的接口和授权方式不一致。

\- 部分网盘无法直接302。

\- 网盘账号政策和API限制需要持续关注。



\## 5.2 推荐组合B：国内 + 海外网盘



| 角色     | 方案                              |

| ------ | ------------------------------- |

| 国内主力   | 115                             |

| 国内辅助   | 夸克或其他已验证网盘                      |

| 海外辅助   | Google Drive / OneDrive / MEGA等 |

| 对象存储   | B2 / R2 / S3等按成本选择              |

| 网盘聚合   | OpenList                        |

| STRM管理 | OpenStrm + 自定义接入适配器             |

| 文件同步   | rclone                          |



优点：



\- 不依赖单一网盘。

\- 可以按资源类型和成本分配存储。

\- 海外网盘可作为额外容量来源。

\- 对象存储可以承担较稳定的程序化存储需求。



缺点：



\- 访问路径复杂。

\- 海外网盘在中国大陆的可用性需要逐个测试。

\- 不同平台的授权、限流和下载策略不同。

\- 需要更完善的网盘健康监控。



\## 5.3 推荐组合C：对象存储为主



| 角色   | 方案              |

| ---- | --------------- |

| 主存储  | S3兼容对象存储        |

| 备份存储 | 另一家对象存储         |

| 接入方式 | S3 API / rclone |

| 媒体索引 | STRM            |

| 播放方式 | 自建鉴权直链或受控代理     |



这种方式更接近正式媒体存储架构，但要特别注意：



\- 存储费用。

\- 下载流量费用。

\- API请求费用。

\- CDN费用。

\- 最低存储周期。

\- 用户访问地区。

\- 服务条款和内容授权。



不能只看每TB存储价格。真正提供视频播放服务时，出网流量可能比存储费更重要。

STRM文件不包含真正的视频内容，因此：



\- STRM文件很小。

\- 海报和NFO等元数据可以保存在本地SSD。

\- 视频文件仍然保存在网盘。

\- Emby扫描的是本地STRM目录。

\## 8.1 推荐播放流程



```text

Emby客户端

&#x20;   |

&#x20;   v

Emby Server

&#x20;   |

&#x20;   v

&#x20;   |

&#x20;   |

&#x20;   |                      |

&#x20;   |                      |

&#x20;   |                      |

&#x20;   v                      v

用户访问网盘/CDN        VPS读取视频

&#x20;   |                      |

&#x20;   v                      v

```



\## 8.2 302直链播放



302的目标是让媒体数据直接从网盘/CDN到达用户。



优势：



\- VPS不承担视频流量。

\- VPS带宽压力较小。

\- 可以降低视频代理成本。

\- 大文件播放不需要经过VPS中转。



需要注意：



\- 302地址可能有有效期。

\- 某些网盘需要特定Cookie。

\- 某些网盘需要特定User-Agent。

\- 部分地址不支持Range。

\- 客户端可能会对重定向后的请求进行不同处理。

\- 需要确认客户端能正常处理鉴权和重定向。



\## 8.3 代理播放



如果网盘不支持真正的302，只能使用代理。



```text

Emby客户端

&#x20;   |

&#x20;   v

VPS代理

&#x20;   |

&#x20;   v

网盘接口

&#x20;   |

&#x20;   v

VPS

&#x20;   |

&#x20;   v

用户

```



这种方式的缺点：



\- VPS需要承担完整的视频流量。

\- 带宽消耗明显增加。

\- 月流量可能很快耗尽。

\- 多用户并发时更容易出现卡顿。

\- 需要正确处理Range、断点续播和连接复用。



不建议将代理播放作为所有网盘的默认方案。



\## 8.4 必须正确处理Range请求



视频播放器经常需要：



\- 请求文件头。

\- 跳转到指定位置。

\- 快进。

\- 快退。

\- 读取不同时间点的视频数据。



因此，播放入口至少要正确处理：



\- HTTP Range。

\- `206 Partial Content`。

\- `Content-Range`。

\- `Content-Length`。

\- `Accept-Ranges`。

\- 合理的超时。

\- 断开连接。

\- 重定向。

\- 访问鉴权。



如果某个网盘只能完整下载，不能稳定处理Range，那么它不适合直接作为Emby主力播放源。



\## 8.5 播放链路测试



上线前必须记录每个网盘的测试结果。



| 测试项目     | 合格标准                    |

| -------- | ----------------------- |

| 首次播放     | 正常开始播放                  |

| 1080P播放  | 连续播放30分钟无异常             |

| 4K播放     | 在目标用户网络下连续播放30分钟        |

| 进度拖动     | 能快速跳转                   |

| 快进快退     | 不出现持续缓冲                 |

| 字幕       | 正常显示                    |

| 多音轨      | 可以切换                    |

| 多用户播放    | 不出现异常互相挤占               |

| URL过期    | 能重新获取有效地址               |

| Cookie过期 | 能识别并告警                  |

| 网络切换     | 能恢复播放                   |

| 客户端兼容    | Android、Windows、电视端分别测试 |

\# 十三、设备绑定与同时播放限制



这部分不能只依靠Emby默认设置，需要额外设计。



\## 13.1 设备绑定



系统记录：



\- UID。

\- Emby User ID。

\- Device ID。

\- 客户端名称。

\- 客户端版本。

\- 设备首次出现时间。

\- 最后活跃时间。

\- 设备状态。

\- 所属套餐。

\- 是否已授权。



示例：



| 设备            | 绑定时间       | 状态  |

| ------------- | ---------- | --- |

| Android TV    | 2026-11-01 | 已授权 |

| Windows       | 2026-11-03 | 已授权 |

| Android Phone | 2026-11-05 | 已授权 |



当用户超过设备额度：



\- 不自动覆盖已有设备。

\- 提示用户联系管理员。

\- 可以提供设备解绑申请。

\- 解绑需要验证用户身份。

\- 设备重置需要限频。



不能只根据IP识别设备，因为家庭宽带、移动网络和IPv6地址都会变化。



\## 13.2 同时播放限制



Emby有会话接口，可以用于查询当前播放状态。



但要注意：



\- 设备绑定数不等于同播数。

\- 在线设备数不等于播放数。

\- 仅仅登录Emby不应该占用播放名额。

\- 需要区分真正正在播放的视频会话。



建议由中央控制器统计：



```text

用户UID

&#x20; |

&#x20; v

查询Emby Sessions

&#x20; |

&#x20; v

识别实际播放会话

&#x20; |

&#x20; v

查询套餐同播上限

&#x20; |

&#x20; v

判断是否允许继续播放

```



如果使用Emby Premiere的原生同播限制，需要根据当前许可和服务用途核对授权。不要将Emby官方许可中提及的设备数量误认为每用户同播数量。



\## 13.3 会话异常处理



需要处理：



\- 用户直接关闭客户端。

\- 播放器崩溃。

\- 网络中断。

\- 会话未及时释放。

\- 两个设备同时抢最后一个播放名额。

\- 用户反复登录和切换设备。



建议设置会话超时机制，并使用数据库事务或锁保证并发检查不会超额放行。

\# 十九、账号安全与合规



这套服务会管理用户账号、支付记录、网盘授权和媒体文件，因此安全不能靠“没人知道端口”这种心理安慰。



\## 19.1 网盘账号安全



\- 不在Telegram群聊发送Cookie。

\- 不在公开日志打印Token。

\- 网盘账号授权信息加密保存。

\- 管理员操作记录审计。

\- 定期检查授权状态。

\- 账号异常时及时冻结自动任务。

\- 不将个人网盘账号密码交给普通用户。



\## 19.2 用户安全



\- 管理员启用双重验证。

\- 用户密码使用安全哈希存储。

\- 登录和设备变更留日志。

\- 支付回调验证签名。

\- 机器人Token不写入公开仓库。

\- 管理接口限制访问。

\- 敏感操作需要二次确认。



\## 19.3 内容与平台规则



应仅存储和提供自己有权管理、存储、播放和分享的内容，并遵守：



\- 网盘服务条款。

\- API使用政策。

\- 对象存储服务条款。

\- 版权和内容授权要求。

\- 个人信息保护要求。

\- 适用的支付和经营规则。



尤其要注意，个人网盘会员资格并不自动等于获得了向其他用户提供商业化播放服务的权利。

\# 二十三、最终架构结论



纯网盘服建议采用：



```text

&#x20;                 Cloud Emby Service

&#x20;                         |

&#x20;            +------------+------------+

&#x20;            |            |            |

&#x20;          Emby        OpenStrm      CloudBot

&#x20;            |            |            |

&#x20;            |       STRM/同步任务    用户管理

&#x20;            |            |            |

&#x20;            +------------+------------+

&#x20;                         |

&#x20;                   网盘接入层

&#x20;                         |

&#x20;         +---------------+---------------+

&#x20;         |               |               |

&#x20;        115            夸克           海外网盘

&#x20;         |               |               |

&#x20;       302优先         代理/适配       按能力测试

&#x20;         |               |               |

&#x20;         +---------------+---------------+

&#x20;                         |

&#x20;                      用户播放

```



最终推荐的技术路线：



1\. 使用现有2C2G30G VPS搭建测试环境。

2\. 优先测试115 + OpenStrm + Emby 302。

3\. 确认完整播放流程后，再接入第二个网盘。

4\. 使用OpenList接入更多国内和海外网盘。

5\. 使用rclone承担备份、同步和迁移。

6\. 对海外网盘建立独立适配器和播放能力测试。

7\. 使用PostgreSQL统一管理用户、订单、设备和媒体索引。

8\. 使用Twilight作为用户管理基础，补充自定义业务控制器。

9\. 使用CloudBot完成注册、购买、续费、求片和通知。

10\. 正式运营前升级至4C8G，并根据实际代理流量和并发决定线路配置。



\*\*最重要的原则：网盘数量可以增加，但播放链路必须逐个验证。\*\*



真正适合成为主力网盘的，不是容量最大、宣传最便宜的那个，而是能够长期稳定地完成授权、文件访问、Range请求、进度拖动和并发播放的那个。
