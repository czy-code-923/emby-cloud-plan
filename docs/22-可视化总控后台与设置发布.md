# 22 独立网页总控后台与设置发布（v6.1）

## 1. 交付定位与结构

目标是一个独立Web管理员后台，统一管理Emby服务、机器人、媒体任务、注册/权益/商店、内容、资源、风控、域名和备份接口。它可以实现，但本仓库目前交付方案/配置/原型，没有真实后端；不能把可点面板说成已控制VPS。

**此总控是浏览器网页后台，与TG面板是两个东西。**管理员直接访问独立地址（如`https://admin.example.com`，示例未绑定），不需要先打开Bot/Mini App，也不依赖Telegram账号来建立总控登录；Bot不可达时仍可经受控管理网络登录总控。总控管理TG菜单/功能/用户面板设置，TG面板不反向承担全部平台设置。

建议沿用唯一业务中心服务，新增admin API、静态前端和受限执行器；不另建一套会改用户到期/积分的后台数据库。TG管理员入口只做状态/待办和受控链接，正式总控优先VPN/隧道或来源限制＋独立MFA，不把“所有TG群管理员”当平台管理员。

### 1.1 三个网页/交互入口的职责

| 界面 | 使用者与进入方式 | 负责内容 | 登录和权限 |
|---|---|---|---|
| TG用户面板 | Bot菜单/命令或TG Mini App | 本人账号、地址、签到/积分、保号、设备、帮助和允许来源码；可选管理员快捷摘要/白名单动作 | 验证TG身份后创建面板会话，仅本人/明确快捷scope |
| 独立网页总控 | 管理员在浏览器直接访问管理地址 | 所有19个模块的配置、用户/订单/媒体/防护/资源/域名/备份/接口/TG管理与发布 | 独立管理员账号＋MFA、管理网络策略、后端RBAC；不接受普通TG面板会话提权 |
| 独立购买网页 | 用户自行访问单独网址 | 商品、付款、人工核款后的取码、完整订单/退款/网页核销 | 购买网站会话与UID映射；不继承总控权限 |

两套管理入口不是两个账本。可以同一代码库/后端进程部署以节省2GB资源，但前端入口、路由、会话audience、权限和发布流程必须区分；实现时可构建两个前端bundle，也可按独立路由构建，不能仅靠一个前端角色选择框实现隔离。

建议`account.example.com`承载用户账户面板、`admin.example.com`承载总控、`shop.example.com`承载购买网站。Cookie使用各自host-only属性，禁止共享跨子域管理员Cookie；普通TG initData或Bot Token不能直接换取总控admin session。若TG快捷操作需要敏感确认，跳到独立网页重新认证，不在Mini App内开放全局策略/宿主执行器。

### 1.2 独立总控的登录和边界

首次部署通过受限本地/CLI一次性引导创建Owner及MFA，禁止公开默认管理员密码；后续独立账号、角色、恢复与审计在总控管理。原型没有实际登录，不把顶栏“演示管理员”当认证。

所有项目支持的配置都应在总控可读/可配置/可执行或明确显示不支持状态；TG管理员快捷功能只是总控的可选子集。总控会话过期不影响普通TG用户会话；TG换绑/退出/Bot故障也不应让独立Owner失去总控访问。共用的账号封禁/权益/账本事实仍通过唯一业务层保持一致。

桌面左侧分组导航、顶栏环境/实例/当前版本、主区表单/待办/执行结果；手机变分组选择与逐块表单。每页同时显示值的来源/作用域、最后更新时间、是否待应用；“模拟”“观察”“草稿”“已生效”“未支持”标签不能混用。

## 2. 全设置覆盖表

| 分组 | 后台可视化设置与操作 | 权限/执行边界 |
|---|---|---|
| 总览 | 健康、在线/同播口径、容量、队列、已收未交付、备份/安全告警 | 不暴露无权的观影/资金详情 |
| 用户与角色 | UID/TG/Emby映射、审核、组、封禁/恢复、限时覆盖、角色/MFA | Owner分权，服务端逐对象验证 |
| 注册邀请 | 开放/邀请/购买路径、总/日/组名额、邀请码、候补、已售未兑预留 | 最后名额事务；下调不随机删人 |
| 权益/保号 | 20天窗口、签到/观影参数、偏好/预约、宽限、免活动grant | 规则新周期生效；安全封禁优先 |
| 积分/码 | 随机签到范围、商品价、目标余额/冻结/冲正、单次码/批次/指定UID、自动续期 | 账本唯一真相、原因/版本、敏感step-up |
| 商品/活动 | 月/年注册、续期、白名单、时长、现金/积分价、份额、限购、定时折扣、下架 | 快照不回溯、未兑承诺占容量 |
| 收款/履约 | 红包/支付宝码/微信码多选、默认渠道、人工核款、差异、发码、退款/对账 | Finance核真实到账；口令不群发，不自动抢红包 |
| TG与外链 | 菜单/命令、消息模板、通知、Webhook/轮询唯一、外链草稿/校验/状态 | 购买外链仅支持待审核配置，默认有效关闭，见第24篇 |
| 帮助/公告/客户端 | 内容版本、受众/定时、兼容/禁用说明、实际执行状态、例外 | 编辑权限与强制拦截发布分离 |
| 媒体/追更 | 来源/订阅/缺集、任务优先级、刮削所有者、路径、四水位、隔离恢复 | 单调度者；不提供批量远程删库快捷键 |
| 网盘/播放线路 | 账号能力、授权状态、来源预算、302/回源策略、可见库/线路 | secret引用，不能显示完整Cookie |
| 设备/会话 | 数量/冷却、实际授权、在途租约、用户/全服/节点同播 | 不把HTTP连接等同播放数；302限制说明 |
| 防扫库/防连点 | 路由组、UID/IP预算、分页、不同条目、去重窗口、来源并发、观察/执行 | 影响预览＋回放，规则不得关闭基本鉴权 |
| 安全事件 | 原因/聚合/冷却、临时白名单、撤限、令牌撤销、申诉、审计 | 有期限/理由；不一键永久封整网段 |
| 资源/任务 | CPU/RAM/盘/缓存/日志预算、并发、72小时证据/建议、总人数/同播 | 受限执行器，应用状态分开，不自动扩售 |
| 域名/IP/TLS | 控制权挑战、A/AAAA、证书、主域/别名、媒体/账户/商店IP开关 | 独立MFA、模板校验、救援入口、回滚 |
| 备份/迁移 | 一致快照、加密/回执/验证、计划/保留、异地目标、预检/切换 | 隔离恢复、控制总额和新水位，非任意导入路径 |
| 游戏积分/接口 | 来源/密钥scope、群/游戏、预算/规则、epoch、关闭/重放预览 | 默认关、关闭阻止在途应用、不得任意设余额 |
| 系统/发布 | 环境、组件/适配器版本、草稿/应用差异、升级预检、配置备份/回滚 | 固定版本/摘要、受限操作，无任意shell/SQL |

以上是项目拥有/支持的设置总入口，不等于可以安全地暴露第三方软件所有内部参数。外部Emby/网盘不支持的能力显示“未支持/需外部设置”，不假写成功；受限跳转只给有资格管理员，不把其管理端口开公网。

## 3. 表单契约和schema

后端返回设置注册表：section、key/path、类型/单位、允许范围、默认/当前/草稿值、作用域、secret标记、读写scope、约束、依赖、应用目标、风险级别、验证器、需重启/维护、版本。由schema生成表单，辅以核款/迁移/积分等专用工作流，不允许用户贴任意JSON覆盖全部配置。

示例：`anti_abuse.playback.coalesce_seconds`单位秒、1～10；`new_unique_items_10m`单位逻辑条目、2～120、默认8并处于观察；`commerce.TG.external_link`为普通HTTPS字段和规则状态，当前Gate阻止发布；`capacity`至少有作用域和单位，不把RAM填成用户数。

所有未填写现金价/收款人/主域必须是明确未就绪，不用0元/空字符串误开销售。字符串转数字用严格整数解析；跨字段约束校验页大小/预算、超时/TTL、硬容量与预留、到期区间、风控白名单有效期。跨页依赖一起预览，不让单页保存覆盖其他配置。

## 4. 从草稿到已应用

```text
读当前版本 → 保存草稿 → 服务端校验 → 差异/影响/回放
→ 短时确认（用途/对象/版本/风险绑定，MFA或step-up）
→ 提交配置版本/审计/outbox → 执行器应用 → 主动探测
→ 标记APPLIED / PARTIAL / FAILED / ROLLED_BACK
```

提交带expected_version、draft_hash、幂等键和原因；他人已更新返回409，保留输入并显示差异，不能最后保存者覆盖先前核款/限额/封禁。secret在单独写入接口仅替换，不回显；变更凭据校验连接但不日志打印请求正文。

修改新开播/人数上限不踢既有合法播放；如果要紧急中断，独立动作显示范围、不可立即收回302的限制和审计。规则“停用”也不能关闭鉴权、删除账本、停掉历史退款或让未兑销售码失去价值。

业务数据库事务和宿主配置不是分布式原子：保存desired_version后执行器校验模板、备份上个已应用版本、原子替换/受控reload、健康检查，然后上报applied_version；失败显示未应用并保留旧版本，不在UI显示虚假成功。回滚配置是产生新版本，不恢复旧业务库，不倒丢最近订单/claim。

紧急入口包括暂停新播放签发、暂停注册/销售/导入、关外部写接口、撤具体令牌/临时规则；每项独立，不提供“关闭所有防护”按钮。救援VPN/隧道、离线Owner恢复材料和最后正常配置不依赖正在被修改的公网域名。

## 5. 执行器与第三方管理

执行器只接受固定operation_id、目标实例、已验证字段/版本和短时操作票据；不接受任意路径、Nginx/Caddy片段、SQL、curl URL或shell。管理API不能公开Docker socket，不授整个后台root文件系统；部署工具按白名单操作reload/cert/资源限制，最少权限并记录结果。

适配器响应超时先查询已应用版本，防重复开通/发码。后台自身有CSRF、host-only Cookie、独立MFA、精确Origin、对象归属、导出限流；生产设置/secret不放前端localStorage或公共日志。备份下载和临时封禁列表按角色脱敏。

## 6. 防护页面和操作例子

页面展示模式、规则作用域/来源、观察命中/实际拒绝、误伤反馈、缓存/队列用量和最后应用版本。选择“重复点同一集”“多剧索取直链”“合法分片”“撤销令牌”回放样例，显示会在何层合并或拒绝；回放不向生产发请求。真实回放数据需脱敏、有限保留，不把所有观影行为导出给内容编辑者。

示例把合并窗口3→5秒：先列影响同UID/同来源重复控制请求，正常分片组不变；确认后记录新版本，执行状态只有收到网关回执才绿色。阈值下调若可能影响已售能力，提示预估范围和过渡；推荐器不能自动降低权益或扩大销售。

## 7. 发电外链控制

技术上可生成“发电/购买”普通URL按钮，目的地限定已验证HTTPS商店域，不能携带用户ID、码/secret、任意跳转参数；但本项目交付注册码/续期/白名单时它仍是购买，不能改称捐赠取得豁免。2026-11-18官方复核没有新的明确许可，当前面板支持草稿保存/预览，生产有效开关仍false。

后台分开显示requested、审核证据/状态、有效enabled、已应用版本。未满足平台适用与商店就绪条件，服务端拒绝发布、用户端不渲染URL；不能由“Owner勾选我确认”伪造官方许可。将来确有适用依据才能按第24篇重新评估，不在本轮偷偷打开。既有独立网站、人工告知、网页核销和售后继续保留。

## 8. 原型与实施顺序

`ui/admin-console-preview.html`提供独立总控交互原型：模块导航、字段草稿、样例防护回放、版本确认/演示发布、外链Gate和脱敏审计。无真实登录/API/服务器操作，不收真实secret；它帮助评审操作流程，不证明后端已具备防护。

实施顺序：先设置注册表/鉴权/版本/审计与只读总览→防护路由和观察→用户/权益/媒体等常规配置→人工核款/码/内容→域名/资源/备份受限执行器。前端构建在本地/CI，VPS只托管静态资源，不在2GB另起开发服务。每阶段交付真实接口、并发/失败测试和已应用回执，再开启对应按钮。
