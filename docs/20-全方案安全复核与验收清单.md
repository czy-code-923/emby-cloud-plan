# 20 全方案安全复核、未决边界与上线验收（v5）

本轮结论：设计覆盖了人工收款、单次码、内容后台、外部积分、异地数据和域名/IP控制的主要风险，但**尚未实现、部署或做渗透/恢复测试**，不能宣称整套系统已经安全。下表是必须落地的控制与验证依据。

v6进一步补齐[第21篇](21-防扫库重复点击与攻击防护.md)防库遍历、重复点击/直链签发、分片兼容和资源耗尽；[第22篇](22-可视化总控后台与设置发布.md)总控发布/执行器安全；[第23篇](23-防护与总控实施验收.md)真实测试矩阵。新增“观察模式”不放松基线鉴权和对象权限，新增静态原型/离线模型不构成实机安全证明。

## 1. 信任边界和权限

公网访客、普通用户、TG群消息、文件/元数据/URL、客户端身份字段均不可信；支付截图和红包提交不可信。独立网页、TG面板、管理员、网盘适配器、Emby、游戏服务、备份VPS分别认证，禁止共享超级Token。

| 角色/机器 | 允许 | 不允许 |
|---|---|---|
| 普通用户/访客UID | 本人订单、码、帮助、申请 | 查别人订单、修改价格、报任意奖励 |
| ContentEditor | 帮助/公告/客户端说明草稿与授权发布 | 收款码/域名/角色/脚本执行；客户端强制拦截发布需Operator/Owner |
| Finance | 本方收款核对、发货待办、受控退款 | 改收款人/价格、读网盘凭据、直接设任意积分 |
| PointsAdmin | 有原因/版本/上限的积分调整 | 核准收款、修改角色/备份目标 |
| Operator | 媒体修复、状态、已授权运维 | 默认无口令红包/支付秘密/完整备份下载 |
| Owner | 政策发布、独立MFA、分配上述权限 | 仍不得绕过审计、幂等和资金事实 |
| 游戏服务身份 | 指定群/游戏奖励申请 | 查全体用户、设余额、活动达标、注册/发码 |
| 备份服务身份 | 指定profile快照上传/下载/确认 | 改生产数据、恢复、删所有历史包、接管Bot |

v2～v4曾把财务与积分调整合在同一“财务”菜单；v5拆权限，可由同一个Owner兼任，但不因菜单可见就继承另一类写入。单人核款没有独立双人复核的保证，应如实说明。

## 2. 风险、控制和剩余限制

| 风险 | 必须实现 | 仍存在的限制/上线证据 |
|---|---|---|
| 伪造付款/一款多用 | 本方实际到账核对、唯一交易引用、金额快照、MFA/审计 | 人工仍可能看错；差异队列、日对账和退款演练 |
| 红包被别人领/泄露 | 独立HTTPS加密短存、仅核款员可见、结案销毁 | 这是可支取秘密，不承诺撤回已泄露内容；不群发 |
| 收款码被换 | 收款人配置发布权限、版本、二次验证、订单快照 | 需运营者核实真实收款账户适用场景 |
| 码被猜/偷/双兑 | ≥128bit随机、HMAC、购买UID绑定、限流、原子claim | 允许重看原文需额外加密；不能仍写只存哈希 |
| 退款和兑码并发 | 锁订单/码、退款状态阻止claim、独立grant撤销 | 人工退款需真实转出确认，无法仅靠API推定 |
| 售卖超额/旧码无号 | 库存＋未兑预留＋容量同事务，续期独立计算 | 未来承载区间也需预算；不是只看当前在线 |
| 外部游戏刷分 | 来源签名/去重/规则/预算/最终epoch校验 | 来源签名密钥失窃仍可发预算内假事件；监测/停用/冲正 |
| 备机被入侵 | 最小scope、加密包、密钥分离、独立保留 | 若备机有解密材料，仍可读敏感数据 |
| 旧包复活码/权限 | 独立最新撤销/核销/核款水位、恢复隔离 | 未齐水位则停交易，不凭旧包直接开核销 |
| 公告XSS/危险上传 | 受限Markdown、净化/重新编码、CSP、大小/像素预算 | 不接受任意HTML/SVG脚本；需恶意样本测试 |
| 客户端伪装/已发302 | 多入口准入、有限策略、明确展示执行状态 | UA可伪造，直链不保证即时撤回 |
| Host/反代头注入 | ACTIVE域白名单、固定链接origin、可信代理网段 | 关闭裸IP不是隐藏源站，须覆盖IPv6和内部端口 |
| SSRF/任意导出 | 固定目的地/路径ID、协议域与解析IP检查、重定向复验 | 允许内网Emby/OpenList必须单独固定授权，不能全面放行内网 |
| 2GB资源耗尽 | 哈希/图片解码/上传/压缩/搜索/队列/请求体硬预算 | 预算值要实测；限流失败不无限生成任务 |
| 供应链/权限过大 | 固定版本/摘要、许可证复核、非root和最少挂载 | 更新前样本回归，不自动latest/远程脚本root执行 |
| 双主重复扣分发货 | 实例fencing/租约、单Bot收件、接管前停旧主对账 | 心跳超时不是可靠自动接管授权 |
| TG规则与付费码范围 | v5.2无购买外链/现金目录，网址人工告知；现金付费码TG默认关、网页核销，Bot查询权益 | 移除网址不自动获得豁免；官方证据、具体外部Emby服务分类边界见第16篇及核验报告 |

安全依据：[OWASP REST](https://cheatsheetseries.owasp.org/cheatsheets/REST_Security_Cheat_Sheet.html)、[上传](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html)、[SSRF](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)；具体阈值和业务状态机是本方案提案，并非这些资料替本项目认证。

## 3. 数据与密钥生命周期

支付密码/短信码/登录Cookie不收集；Emby密码和安全码不持久化明文；验证码/票据短时且用途绑定；红包口令短存并销毁；交付码只有需要重看时分离加密；卡码核销、退款、积分与审计不可原地抹除。资金/争议资料保留按实际义务与最小化原则配置，不假定所有数据统一30天删除。

Bot Token、网盘凭据、签名密钥、码HMAC密钥、码交付加密密钥、备份加密公私钥、DNS令牌分开，记录key_id/用途/轮换和历史解密需求。禁把真实资料加入GitHub；日志/告警/导出/访问分析分别脱敏，不只检查应用日志。

用户关闭账号需先处理在途订单/未兑码/退款/争议，暂停新消费并说明可保留部分记录；不能删UID后让同一Telegram身份重复领取新客或丢退款责任。账号恢复与TG换绑不凭订单截图，恢复旧备份默认撤会话、临时票据和恢复码。

## 4. 必须失败的越权请求

- 用户A查看B的订单/码/截图/导出、转发管理员待办链接、伪造TG initData/UID或游戏中奖数据。
- 普通客服读红包秘密、内容编辑者改收款人/强封客户端、Finance直接改钱包、备机调用恢复或游戏奖励。
- 重放已成功确认请求、同交易引用多单、同局换event_id、nonce复用、关接口后应用旧排队任务。
- 任意上游URL/导出路径/证书路径、恶意重定向到云元数据、IPv6回环/私网、压缩炸弹和超大像素图片。
- 裸IP/未知Host/伪造代理IP进入后台、错误CORS带Cookie、关闭商品后绕过服务端直接创建新订单。

返回最少必要错误，不泄露码是否由他人使用、某TG是否注册或数据库结构；安全日志可按引用号查脱敏细节。

## 5. v5上线验收场景

| 组 | 要完成的测试 | 通过条件 |
|---|---|---|
| 人工收款 | 三渠道单独/组合/全关、截图伪造、红包失效/被领、实付不符、迟到款、通知失败 | 不自动视为已付，保留可追踪人工差异与资金责任 |
| 商品促销 | 调价、限时结束、下架、最后份额并发、已售未兑容量、退款恢复库存 | 快照不漂移，不超卖，既有订单不会被静默作废 |
| 发码核销 | 2人并发核准、重复通知、双端兑码、错UID、退款并发、Emby失败、换码 | 一份交付/一次claim，时长从兑码起算，故障能恢复 |
| 内容/客户端 | 草稿/定时/回滚、注入/恶意图、范围公告、禁止UA和绕路入口 | 内容隔离，显示和硬执行不混淆，误封可恢复 |
| 外部积分 | 验签、时钟、重放、换ID、预算并发、在途关闭、补偿 | 只入合法一次钱包，不改变签到活动分，不突破预算 |
| 异地备份 | 只读scope、半包/错hash、备机满盘、撤权限、旧包恢复、主备切换 | 最新水位可证明，已用码不复活，无双主发货 |
| 域名/IP | 未持有域、A/AAAA/TLS、Host注入、IPv4/6开关、代理头、解绑/换域 | 仅受信入口服务，管理和内部端口仍隔离 |
| 性能与恢复 | 2GB下同时核款/播放/签到/备份、磁盘阈值、停电/重启/DB故障 | 不丢账、不双发，记录实际资源和恢复耗时 |

先在隔离测试身份和无真实资金环境执行，付款正式发布前另以允许渠道小额验证核款/退款。安全测试、真实收款和部署不在本次方案编辑范围；本地验证只能证明文档/配置/模型/原型的一致性。

## 6. 本轮补齐的漏项与仍需填的数据

已补：可重发原码需要加密交付副本；销售份额与未兑码承诺分开；下架不取消已售责任；付款口令不进普通备份；核销/退款并发与旧快照复活；备份关闭不回收已传字节；来源关闭要挡在途入账；内容编辑与客户端强封/财务权限分离；关闭裸IP不等于封锁源站；访客购买先有可认证UID、不先建Emby账号。

实施前仍需填写：实际网盘/Emby及插件版本、磁盘/月流量、域名与DNS控制、实际现金价格、收款账户适用场景、值守时间、退款条款、备份VPS/密钥保管者和预计售卖人数。缺值的销售/接口保持草稿或关闭，不影响本方案完整性，也不虚构已经可运营。
