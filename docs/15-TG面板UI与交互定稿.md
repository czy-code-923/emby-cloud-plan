# 15 TG用户面板与受限快捷交互（v8）

## 1. 双入口、同一业务

用户Bot原生菜单承担随时可用的快捷操作，Mini App承担用户图形自助面板，两者调用同一业务后端。原生按钮保持两列、每屏主要操作不超过6项，其余分组；Mini App默认五个底部入口：首页、追更、签到、兑换、我的。可选管理员快捷视图：总览、用户、任务、容量、设置，仍受快捷scope限制。

这里的TG管理员视图只是可选受限快捷子集，**不是独立网页总控**。所有全局设置、规则发布、角色/MFA、域名/资源/备份执行均由第22篇的网页后台统一管理。旧原型中的管理表单是流程预览，不意味着TG身份能直接获得总控权限；网页总控具有独立地址、登录和会话，不依赖打开Telegram。

v5增加帮助/公告/客户端页、已有订单/单次码、管理员人工核款与内容/接口设置预览；独立网页收款演示与TG面板在预览入口明确区分。口令/二维码不嵌入TG结账，实际渠道/鉴权见第16～20篇，演示切换器不是安全控制。

v5.2移除v5.1“打开购买网页”按钮和处理分支，TG页只显示“积分与兑换”、本人权益/核销；现金目录、价格、渠道和完整订单留在独立网站，网址人工告知。设计预览器切换“独立网页”是会话外的测试控件，不是Bot功能或购买跳转。付费码TG生产入口默认关闭，原型的虚构码仅演示一次核销，不代表实际付费码获准。

本仓库`ui/tg-panel.fragment.html`是可点击的界面设计原型，`ui/panel-preview.html`是本地预览；全部使用演示数据，不连接Emby/网盘/Telegram、不修改真实积分或权益。正式权限与交易不能在此原型里实现或验证。

## 3. Mini App页面结构

| 页面 | 首屏必须看到 | 主要操作 |
|---|---|---|
| 首页 | 当前播放权益、模式/豁免、余额、服务状态 | 地址、签到/续期、查看异常 |
| 追更 | 我的订阅、已可播季集、获取/整理/索引状态、最后成功 | 关注/取消、求片、报告缺集 |
| 签到 | 随机10～20分、今日状态、钱包/本窗已签天数、月卡缺口、预测假设 | 一次签到、查看流水、查看/切换保号方式 |
| 兑换 | 月/季/年积分价、允许来源码、天数、免保号效果、资格 | 预览→确认→到账结果，无现金入口 |
| 我的 | 用户、线路、设备/同播、订单、安全、通知、帮助 | 改密、安全码/恢复码、绑定、导出 |
| 管理总览 | 人数/同播口径、任务/来源/备份异常、最新数据时间 | 深入异常，不放无意义评分 |
| 管理用户 | 查UID、可用/冻结积分、权益/模式、覆盖来源 | 加减/设目标、授权、恢复，均留原因 |
| 管理任务 | 来源发现→取得→索引→播放四水位、队列、错误 | 有限重试、暂停、匹配修复 |
| 管理容量 | 现配/实际占用、建议、证据、未知、作用域 | 影响预览→发布→执行/回滚状态 |
| 管理设置 | 随机范围、积分商品价、注册、规则版本、备份与安全 | 草稿预览、校验、Owner确认 |

追更界面借鉴[MoviePilot](https://github.com/jxxghp/MoviePilot)的任务组织，求片/库存体验参考[Seerr](https://github.com/seerr-team/seerr)；只借鉴职责与交互，不复制其界面代码，也不暗示它们已有本项目积分或保号功能。

## 4. 签到交互

点击前展示范围和平均值；点击后立即禁用并显示处理中。只有服务端提交成功才更新奖额、钱包和签到日期，之后展示独立自动续期结果；重试返回原凭证，不在前端重新抽。

结果示例：已选A且授权有效，“今日＋16分，284→300→自动扣300，余额0；本窗已签20天；原到期顺延30天”。B或未启用的免保号用户则保留300分，可主动兑换免保号卡。已签再次点击显示今日原奖额/时间，不重复动画暗示新抽奖。

钱包进度、本窗签到日期/天数、本月赚分是不同数据。预测显示“从当前缺口计算，参数不变；平均/概率不等于保证”，默认给简短说明并可展开完整测算；不要让用户每天阅读公式。

## 5. 保号方式、冷却与免保号尾窗

两卡分别为“A：可用够300自动扣款，原到期＋30天活动时长”“B：本30天窗有效观影30分钟免费自动续30天”。显示窗口起止、已签到N天/日期、观影进度、余额/缺口、当前方式、最近实际变更、next_switch_at与授权。A不是免卡，旧活动分条删除。

首次选择/真正A↔B变更才启动20天冷却，满后重选权一直保留，实际变更即时生效；同方式确认、续期/买卡/迁移不重置。已结窗下一窗未开始则显示“下一窗待开始”，不靠切换重复续期。

免保号默认无需选择/无活动义务，仍可签到。剩余≥30天/永久不显示选择；严格不足30天才可自愿启用A/B，历史偏好不暗中扣款，不选则保留原权益直至到期。启用不损失豁免剩余；新卡延长则暂停参与并在未来尾窗重新明确启用。详见第29篇。

## 6. 商店与交易反馈

积分卡卡片写“30天免保号播放，300分”，不能只写“保号月卡”。兑换预览列：扣多少、余额变化、生效/到期、顺延/换档、设备/同播/库范围、退还条件。提交期间锁按钮；成功展示grant及同步状态；漏履约显示权益已记账但同步中，绝不再次扣款。

真实购买未开放时禁用购买并解释，积分商品可独立工作。价格改变、余额并发变化、库存不足返回重新预览，不能按旧页面价格悄悄提交新价格。

独立网页月/年注册、续期码、白名单有份额/限购和活动价；人工核款后码已发但未兑不显示播放已生效。用户订单展示待核、码已发、核销和同步状态；帮助和公告由后端版本化发布，禁用清单显示建议或已执行，不凭原型宣称强拦截。

## 7. 管理员页面操作

用户页“设置余额”必须给当前可用、冻结、目标、差额和原因；保存请求携带版本，冲突时保留输入并刷新预览。批量改积分先显示名单和总差额；大额/权限变更需后端安全码/MFA规则，不只前端确认弹窗。

容量页分别显示总注册、活跃成员、在线、全服同播、每节点同播。减少上限时写“已有会话保持，暂停新增至低于上限”，若实际不支持宿主执行则显示待应用。推荐按钮只生成建议，不自动扩售。

备份/迁移页将预检与执行分开，展示快照时间/版本/校验/异地/对账状态；未解密、未核对时不得出现绿色“恢复完成”。

## 8. 视觉与可访问性

Telegram浅色/深色随宿主，主色克制，正文与状态保证对比；卡片标题、金额和单个主要操作清晰。手机360px、320px兼容，平板/桌面按内容扩展；固定底部操作需要预留安全区，键盘弹出不遮输入/确认。

真实产品不展示内部Token、完整路径和数据库细节；技术错误用友好原因＋引用号，管理员才查看脱敏诊断。最小触控目标约44px，键盘可操作、焦点明显、读屏有标签；不能只靠红绿表达状态。

加载、空数据、无权限、上游错误、部分成功、重复提交、断网、过期按钮都有设计。列表分页，后台页隐藏暂停轮询，数据请求合并缓存；不在2GB服务上为面板每秒全量刷新海报和全库统计。

## 9. 交付验收

原型验证页面切换、签到一次、兑换预览/确认、模式锁定提示、管理员余额表单、容量降额预览与320/360/768/1440px布局。正式开发另测initData、对象归属、重放、版本冲突、账本事务和敏感操作，不把静态原型通过当成安全功能通过。

## v7.1 限频与注册排队状态

连点优先返回处理中/原结果，不能每击新发一条消息；冷却文案显示范围和重试时间，不泄露码是否存在。本人注册进度显示ticket、排队/执行/等日额/等容量/核实中、更新时间、建议查询时间/取消；不承诺精确位置/完成时间。限频/安全/实际开户在后端统一执行，前端按钮禁用只是提示。独立总控新增三页设置见第28篇，不把用户TG面板当全局队列管理。
