# 24 TG“发电”购买外链当前选择（v6.0）

核验日期2026-11-18。用户重新提出：机器人增加可点击外链购买注册码、续期码和白名单，总控可配置。本篇记录技术可实现性、当前规则证据和默认决定，取代将v5.2选择误读为平台永久禁止所有普通URL的说法。

## 1. 当前选择

技术上普通URL按钮可实现；总控保留名称、HTTPS目的域、草稿预览、请求启用、有效状态和关闭的配置能力。当前requested=true表示记录用户需求，**effective_enabled=false**；不生成面向用户的购买链接、不嵌入付款，也不替用户发消息。

“发电”若换取注册、时长或白名单权益，仍按购买设计，不当成无对价捐赠来规避数字支付规则。只有真正无对价捐赠才是另一场景，本方案不把已有商品重新贴标签。

没有找到比2026-11-13核验更明确的本场景许可，继续沿用用户此前授权的备选：独立网址人工告知、网页购买/核款/发码/核销，TG免费管理与权益查询；付费码TG核销保留能力、生产默认关。新请求已记录为待审核功能，不能据此宣称平台已批准。

没有新的普遍豁免证据，因此不能保证“Bot只跳网站”“叫发电”“网站手动核款”“购买卡码”中的任何一项让本项目必然获准。外部Emby服务与免费管理Bot具体分类仍有边界，未向Telegram发出个案询问、未获书面许可；表中是公开资料核验，不伪装成官方个案答复。

## 3. 总控内的待审核外链

记录字段：requested、label、草稿URL、验证过的目的域、入口Bot/语言、显示对象、policy_review_status/evidence/date、shop_ready、enabled_requested、effective_enabled和applied_version。草稿不对普通用户返回；默认URL为空。

提交时验证域名控制权、HTTPS、无userinfo/片段/身份/secret/任意return_url、不跳未知域、商品/收款适用就绪，以及规则适用证据。审核状态未满足或证据不支持时返回`POLICY_REVIEW_REQUIRED`，即使Owner勾选也不当作官方许可；不能只由客户端传`approved=true`解锁。

只有后续得到明确适用依据并更新审核记录，才能重新决定开启普通URL按钮；如果需要Stars路线则另立有退款/对账的实现任务，不在本轮自动开通。面板显示“技术可配，规则待确认，当前关闭”，不会显示“已开通购买”。

若最终开启，按钮点击只导航不建单/不自动登录/不占位，网站重新验证UID；URL不含TG ID、码或令牌。关闭则撤菜单/回调/模板、短时缓存和用户配置响应，仍保留历史网页订单/退款/核销责任；已被复制的历史链接无法保证收回。

## 4. 配置与验收

`config/commerce.example.yaml`记录待审核状态；`config/admin-console.example.yaml`将它放在TG与通知设置中。原型只显示草稿/Gate，不打开真实外链，不接收现金或secret。第23篇给出目的域、越权发布、旧按钮和关闭后的验收条件。
