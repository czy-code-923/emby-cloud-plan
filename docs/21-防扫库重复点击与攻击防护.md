# 21 防扫库、重复点击和攻击防护（v6.0）

日期2026-11-18。本篇是拟开发网关/控制器的实施契约；当前没有部署防护设施。所有数值是2核2GB小范围邀请制的起始提案，行为限制先观察72小时，再按真实客户端回放启用；鉴权、对象归属、内部端口隔离和请求尺寸边界不能等待观察期才实施。

## 1. 保护目标与可实现边界

保护对象包括：媒体库/用户信息、播放签发与网盘API预算、VPS CPU/内存/带宽、账户/积分/订单/码、管理员与备份。防护要降低自动化批量获取和重复请求的成本，避免一个账号/脚本占满服务。

“防扫库”分为未登录探测、有效账号批量遍历元数据、随机ID探测、批量索取直链、绕过网关访问源站。普通用户为浏览而得到的片名/海报无法保证绝不保存；已签发上游302地址也无法由本系统随时撤回。目标是最小授权、限制批量、发现异常和可恢复处置，不承诺绝对防爬、防录屏或防所有盗链。

重复点同一剧集与正常播放器发起多次请求必须分开。同一播放可有PlaybackInfo、探测HEAD、Range、音轨/字幕、HLS分片、心跳、断线续传；不能把每个HTTP请求当作一次观影/新开播，也不能用“一链接只能访问一次”破坏正常播放。

## 2. 分层设施与2GB选择

```text
提供商DDoS/网络入口 → TLS反代（请求尺寸/超时/粗限流）
→ 统一业务/媒体网关（认证、对象权限、分组预算、去重、准入）
→ Emby/播放适配器/网盘（内网）
→ 事件聚合、短时风控与管理待办
```

| 层 | 首期设施 | 说明 |
|---|---|---|
| 网络 | VPS提供商已有DDoS能力、主机只开必要端口、IPv4/IPv6一致隔离 | 大流量打满上游须提供商清洗/更换受保护入口，主机脚本不能凭空增加带宽 |
| 反代 | 当前Caddy保留，结合真正覆盖媒体流量的控制器/网关 | 不能只限Bot API而漏放Emby入口；Caddy标准包不被假定自带通用rate_limit指令 |
| 替代反代 | 若需要成熟现成的IP请求/并发限速，可验证Nginx官方limit_req/limit_conn，替代当前入口 | 不为此同时叠两套公网代理；证书续期、WebSocket、Range和302都重新验证 |
| 业务网关 | 同一控制器内的已认证UID预算、播放合并、路线分类、权限检查 | 是拟开发能力，不是宣称Emby/OpenStrm/Twilight已有这些功能 |
| 主机登录 | SSH密钥、限制管理来源、独立MFA；可选现有Fail2ban | 只消费可信认证失败日志；不因任意客户端写的用户名触发全账户永久禁用 |
| 扩展WAF/行为引擎 | 4GB以上或外置节点再评估，按实测与规则覆盖取舍 | 首期不强制再装大型WAF/Redis/日志搜索全家桶 |

Nginx请求速率与连接限制有不同语义；HTTP/2/3下并发请求也可能分别计入连接限制，不能把连接数写成正在播放人数。Caddy模块清单中的rate_limit是非标准扩展，若选它必须锁定源码/构建版本并承担维护。[Nginx请求限制](https://nginx.org/en/docs/http/ngx_http_limit_req_module.html)、[连接限制](https://nginx.org/en/docs/http/ngx_http_limit_conn_module.html)、[Caddy模块说明](https://caddyserver.com/docs/modules/http.handlers.rate_limit)

## 3. 固定版本的路由覆盖清单

先抓取已授权样例客户端的脱敏请求，建立`route_profile_version`：规范方法/路径别名、用途、认证方式、权限对象、限流组、数据/控制面、允许体积/超时、是否产生新签发、测试证据。明确`/emby`前缀和无前缀等实际别名，大小写/编码规范化一次，拒绝路径穿越、歧义编码和重复冲突参数；不靠片名/路径字符串包含`Items`就判断安全。

覆盖列表/详情/搜索/图片/字幕/下载/原文件、PlaybackInfo、直接流、HLS/DASH清单/分片、会话/心跳及用户相关API；本篇不虚构固定Emby版本的完整路径列表。公开登录/服务发现仅开放客户端必需最小字段，用户列表与管理API不能被透传默认公开。

只有服务端验证的用户令牌可以确定UID和库权限；请求里的UserId、DeviceId、Client/UA只是声明。禁用公开管理员API Key、匿名STRM目录列表和文件路径；网盘/OpenList/适配器管理端口不直接暴露。Emby用户认证与服务器API Key用途不同，路由和字段按部署版本API Browser核对。[Emby REST说明](https://dev.emby.media/doc/restapi/index.html)

## 4. 防库遍历和信息枚举

1. 列表和搜索只查本人可见库/类型，所有详情/图片/字幕/播放请求再次校验对象权限；不可因知道ItemId直接读取他库。服务端不把管理员查询结果未经用户过滤返回。
2. 列表单页默认50、最大100条，批量ID最大50、关键词2～80字符；省略分页参数时应用安全上限，超额参数返回可读400/422，不先查全库再裁剪。原生客户端若确有更大批量需求，建有证据的限时客户端profile，不一刀切破坏兼容。
3. 限制递归/多重筛选/排序/昂贵字段组合、请求体和响应尺寸；分页扫描仍计预算。客户端改变offset、排序、查询字符串或随机无意义参数不重置UID预算。支持的参数从Emby版本映射，未知高成本组合拒绝/需授权，不允许任意SQL/导出。
4. 元数据接口提案：每UID每10秒最多20次、每分钟120次，搜索每分钟20次；图片另组每10秒120次并限制图片尺寸与并发，不能把首页几十张海报算成20次扫库。并行多设备共享UID预算、另有可信会话上限；NAT下IP只用高阈值粗保护，不把家庭多人误当一个人。
5. 单UID 10分钟中请求>300个不同条目详情，或1分钟大量顺序分页/随机ID失败，先进入观察/降速；去重计数只保存有限窗口摘要，不常驻全库。大库用户快速浏览、演员页、多季列表可能触发，首期只记录，结合签发/错误/持续性再开启临时限制。
6. 批量导出库/列表、下载和大范围媒体操作只给授权角色；普通播放器不提供整库导出。一键刷新、搜索全库和求片自动化都有任务配额，不能借“播放失败重试”不停触发扫库。

ID随机化或隐藏按钮不是鉴权；有权读到的内容也可能被低速采集，单账号限流不能单独解决多账号协作。邀请/注册节流、活跃名额、来源预算和告警共同约束，不宣传“有验证码就不会扫库”。

## 5. 同剧集反复点击与播放请求去重

建议顺序：外层尺寸/来源粗限流 → 令牌验证/撤销版本 → 对象/库/封禁/设备策略 → 已有播放实例/短时合并 → 新开播/签发预算 → 并发准入 → 上游签发/回源。不能先查到302缓存就跳过用户权限。

同一UID＋已验证会话/设备上下文＋逻辑条目＋实际来源版本＋播放规格＋权限epoch＋必要UA/IP签发上下文，在3秒合并窗口内复用同一个**已授权结果/在途任务**。客户端自报PlaySessionId、随机query和时间戳不能单独打散合并键；不同来源/码率/权限/用户不可乱合并。seek位置通常不新增上游直链，确需依位置区分的协议单独测试。

在途合并必须有有限等待（提案2秒）与有限等待者（每键20、全服64），超额立即429/短重试，不无限排队等网盘。上游调用超时5秒起步、每来源最多1个新签发在途，播放优先；超时不代表已失败，查询/幂等后有限重试，取消后关闭未使用的上游连接。

原始新播放控制请求先按每UID/条目10秒最多20次保护；这是防脚本入口，正常分片/心跳不进入该组。合并成功不再次占用同播、生成新会话、扣费、累计观影或反复调用网盘。合并过期不代表一定要新签发，若已有合法会话和有效短缓存则可继续复用，仍重验权限。

起始提案：真正新开播每UID滚动60秒最多10次；不同条目新签发每UID滚动10分钟最多8个。后者先观察，防用户快速试看误封。同一正常会话刷新签名/过期重连单独受控，不能每续心跳都耗新条目额度；它也受全服/来源新签发预算约束，不能无限豁免。

同一个毫秒100次重复点同一集的离线目标例：20次通过原始控制预算，其中1次新签发、19次复用，80次短时429；不是100次都访问网盘。正常10次短时重试可1次签发＋9次复用。这个例子假设鉴权/缓存键相同且无额外瓶颈，不代表实机并发结果。

## 6. 视频数据面和真实302

| 请求 | 正确限制 | 避免误伤 |
|---|---|---|
| HEAD/Range/拖动 | 绑定合法播放上下文；按同实例复用签发，异常小碎片/多范围有预算 | 不把每段字节请求视作新开播，不强制每段输入验证码 |
| HLS/DASH清单与分片 | 同UID会话下独立数据组，初值20次/秒、突发60，按客户端段长校准 | 不共用10次/分钟开播阈值；短分片可高频 |
| 心跳/播放进度 | 验证播放实例、采样去重、可合并，预算独立 | 不影响真实观影计时，重复上报不增有效分钟 |
| 图片/字幕 | 对象权限、尺寸/字节/并发、合理缓存 | 多张海报/语言切换不是批量开播 |
| 原文件下载 | 首期关闭或明确授权，所有别名路径受控 | 不只在前端隐藏下载按钮；业务白名单不自动豁免 |
| 302外部CDN | 授权后签发，上游URL仅短时内存缓存、日志脱敏 | CDN后续字节/链接转发不都经过VPS，无法靠本机统计绝对防盗 |

自有控制器的签发票据可短时、绑定UID/条目/上下文和epoch；兑换票据只换一个合法播放上下文，不把上游Range或分片URL做成不可重用的一次性码。签名本身不能代替用户权限，前端不会获得网盘Cookie或管理员Key。

HLS、直流和302不能照搬一个响应缓存策略；鉴权前不共享用户响应，含签名地址禁止公共CDN缓存。绑定IP只能作为网盘必要上下文，移动换IP时重新授权可用，不能默认永久锁IP。302已发链接上游TTL由网盘决定；若必须强回收/严格流量计量，需转为受控代理并承担带宽/隐私/成本，2GB不默认开启无限回源兜底。

## 7. 防滥用响应、冷却和人工复核

每个规则有scope、观察/执行状态、版本、原因码、首末触发、计数窗口、当前动作/截止和申诉。默认行为：超预算429＋Retry-After和引用号，播放器返回协议适配的错误，不返回一整页HTML验证码。短窗重复违规可先30秒、再5分钟只限制新开播/列表；不因一次429直接封号、扣积分、删库或取消付费权益。

未授权401、已确认无权403/不泄露对象的404、输入过大413/422、限流429、上游维护503分开。403/404探测只能作组合证据，错误率不能把正常缺海报当攻击；客户端故障风暴先暂停异常任务或隔离客户端profile。安全确认的令牌泄露可立即撤销令牌/新授权，具体已有302仍受上游限制。

账号/IP/来源网段分层；禁止仅因X-Forwarded-For可伪造值、UA变化、IP换网、单个无效用户名永久封人。IP临封默认10分钟、可撤销、需理由；自动不扩大到整个/24或IPv6 /64，若有确证人工升级须展示受影响范围。操作员白名单只豁免特定限流规则且有期限，不绕过鉴权、硬容量或财务事务。

## 8. 其他攻击的必要防线

| 攻击/滥用 | 措施 |
|---|---|
| 撞库/暴力登录/恢复码猜测 | 同账号哈希与可信IP双预算、渐进冷却、管理员MFA；用户名是否存在统一响应，账号级冷却不永久阻断播放 |
| TG连续点击/重放/验证码枚举 | 逐次归属、update/callback去重，UID动作预算；签到/积分/码/订单沿用账本唯一键；先答callback再排队，不重复生成昂贵任务 |
| CC/Slowloris/超大头体/畸形方法 | 头体字节、头/读取/空闲超时、写入路由方法白名单、最大响应、在途并发；视频长流单独超时，不全站5秒切断 |
| SSRF/内网探测/文件路径穿越 | 来源/回调/备份目标固定允许集，DNS/重定向逐跳检查，允许的内网Emby/OpenList精确登记；媒体名不拼shell |
| XSS/SQL注入/恶意NFO/上传炸弹 | 参数化访问、受限Markdown、净化、图像重新编码/像素上限、压缩/解包比率和路径保护，不执行用户脚本 |
| CSRF/IDOR/会话盗用 | 安全Cookie、短会话/step-up、对象授权、配置epoch、精确CORS，不能拿用户ID代替身份 |
| 队列/日志/缓存爆炸 | 有限缓存键/队列/事件采样/聚合、日志轮转，未知随机ID不无限占缓存，避免每次攻击都同步写DB/发TG |
| Webhook/奖励/支付伪造 | 逐来源签名/密钥/scope/时间/nonce/幂等，预算最后提交重验，人工款按实际到账，不凭截图 |
| 资源竞争/断网故障 | 播放/核款高优先、暂停导入/扫描/图片重任务；故障不能自动删媒体或随机踢既有用户 |
| 供应链/宿主接管 | 固定版本和摘要、最小挂载、无任意shell/SQL/特权容器，独立密钥/只读媒体和管理隔离 |

措施依据和适用范围参考[OWASP DoS防护](https://cheatsheetseries.owasp.org/cheatsheets/Denial_of_Service_Cheat_Sheet.html)及[REST安全](https://cheatsheetseries.owasp.org/cheatsheets/REST_Security_Cheat_Sheet.html)。这里的具体阈值/动作由本项目设计，不是外部资料替本机安全背书。

## 9. 硬预算、故障与可观测性

2GB初值：风控状态缓存上限16MiB/10000键，合并等待者64个，来源新签发并发1；鉴权/路线缓存与状态分配有总上限。估算内存还需语言运行时/锁/连接开销，不能只看键文本大小。应用多进程/多VPS后不能各自独立给一份额度；共享原子计数/租约或按保守分配，没完成前只启单网关执行者。

基线鉴权不可用不发新直链/新租约。行为计数缓存失效时保留本地保守限流与全局来源预算，暂缓新高成本签发，不把“风控故障”当无限放行；已有播放依第05篇的有限降级，安全撤销epoch不能被旧缓存覆盖。风控规则观察模式只不执行行为处罚，不关闭身份/权限/尺寸边界。

后台看：按路由组的允许/拒绝/合并/上游签发数、唯一条目数、排队/缓存占用、拒绝原因、P95延迟、来源429与命中后实际误伤；不要把所有429累加成“攻击次数”。安全事件脱敏、最多每分钟聚合同一原因，IP仅短期摘要，普通管理员不查看全量观影史。降低误报有过期白名单/撤限/规则回滚和可达支持通道。

## 10. 发布顺序

固定客户端/路径覆盖→设置硬边界→72小时行为观察和正常会话回放→预览会命中的UID/路由与估算影响→Owner/安全操作员发布版本→小范围执行→比对拒绝率/延迟/实际投诉→应用确认或回滚。不得以一条Nginx限流配置就声称整套防扫库已验收。

配置示例见`config/anti-abuse.example.yaml`；离线模型仅验证部分计数/去重/鉴权顺序，不能验证真实网关并发、网络攻击或所有客户端。实测矩阵见第23篇。
