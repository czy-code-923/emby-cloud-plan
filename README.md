# 个人云盘 Emby 与 Telegram 服务完整方案

版本：4.0 · 规划日期：2026-11-13 · 状态：设计完成，附交互原型，尚未部署或压测。

以现有 **美西 2核2GB VPS＋网盘**起步，先跑通直播放、自动整理刮削、增量更新和 Telegram 自助服务。注册支持开放、邀请、购买及其组合；后续升级服务器时沿用同一套用户和权益模型。

本仓库存放方案、规则示例和验收清单。配置示例是拟开发系统的设计输入，不是已经实现的软件配置。真实域名、密钥、网盘凭据和用户数据不应提交。

## 推荐决策

1. 单机 Docker Compose；Emby＋一个已验证网盘适配器＋CloudBot/控制器＋PostgreSQL＋Caddy。初期不强制部署 Redis、Sonarr、Radarr、CloudDrive2 或监控全家桶。
2. 当前优先OpenStrm＋有效内网取源映射，缺少现成映射时验证内网OpenList并计入内存；Emby负责自动刮削。115为验证候选，其他网盘逐个测试，不能把能挂载当成能302。
3. 参考Twilight、MoviePilot、Wizarr与Seerr，优先验证复用Twilight作为唯一用户业务底座，定制规则在同一服务扩展；不并行另一套会改余额/到期的用户中心。
4. 免费用户选择**签到积分保号或观影保号**，每20天一个选择/考核窗口，可预约下期切换；按所选模式考核，不随时重置周期。
5. 积分兑换和购买在活动之上：月/季/年卡有效期内**免签到、免观影**。积分价提案300分/30天、850分/90天、3000分/365天，均可调整；签到活动分与钱包分离。
6. 302 场景可以控制新播放授权、识别常规客户端和统计上报会话；不能承诺绝对设备防伪、精确 CDN 字节计量或立刻收回已签发直链。
7. 机器人数字商品支付按 Telegram Stars 设计，初期真实支付默认关闭；积分商品、管理员赠送和兑换码可先实现。
8. TG原生菜单＋Mini App面板，独立安全码/恢复码，管理员单用户积分与权益覆盖，后端统一鉴权与审计。
9. 自由设置全服/节点/网盘/用户的资源、人数与总同播。系统识别VPS给有证据的建议，不自动扩大售卖容量。
10. 备份验证、隔离恢复、跨VPS/业务中心/网盘迁移具有预检、对账与回滚。
11. 每日钱包签到改为10～20分整数等概率，平均15分；月卡300分，从零余额平均20.4889次签到，22次达标概率98.0433%，30次保证足够。本期活动分仍固定10分/日，不被随机运气影响。
12. 媒体采用唯一任务调度、唯一元数据所有者、唯一Bot收件者；复杂来源路线再评估MoviePilot，AutoFilm＋MediaWarp作为替代组合，避免重复组件相互覆盖。

## 已确认与尚待确认

- 已确认：美西2核2GB，未来可能升级；三种注册；活动方式每20天可重选；兑换/购买有效期间免保号。
- 原方案提到 30GB 磁盘，本次未确认实际剩余空间；VPS 月流量、网盘、Emby 版本、域名、用户规模均待填。
- 默认设计：邀请制启用、开放注册和购买注册可在后台开启；免费保号规则为提案，可配置，不是已经生效的服务条款。
- 未执行：VPS 部署、网盘授权、支付开通、真实用户操作与实际播放测试。

方案中所有内存、延迟、并发和调度值都是起始预算或验收目标，不能视为当前服务器测试结论。第三方能力核验与来源见[参考说明](docs/07-资料核验与待定参数.md)。
