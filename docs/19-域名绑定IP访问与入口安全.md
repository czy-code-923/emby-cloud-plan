# 19 域名绑定、IP访问与入口安全（v5）

## 1. 入口分开绑定

| 入口 | 建议示例 | 默认网络策略 |
|---|---|---|
| Emby播放 | `emby.example.com` | 公网HTTPS，经唯一播放网关；原端口不直接公开 |
| 用户账户/TG Mini App | `account.example.com` | 公网HTTPS，受限路由＋会话；高风险再次验证 |
| 独立网页商店 | `shop.example.com` | 公网HTTPS，独立浏览器入口上下文；人工支付只在此启用 |
| 管理后台 | `admin.example.com` | 默认VPN/隧道，必要时指定管理来源＋强认证 |
| 外端备份/积分接口 | 专用私网入口，或主域受限路径 | 默认关闭，开启时独立机器鉴权与scope |
| 轻量状态/健康 | 独立受限路由 | 公共只给最小状态，版本、DB、用户、密钥不返回 |

一台VPS多个域名不是多节点。可同站不同路径，但Cookie、CORS、CSRF和权限仍按应用区分；优先独立子域、host-only Cookie，不把管理会话发给媒体域。业务地址生成只读受信任的已发布endpoint配置，不从任意Host头构造改密/发货链接。

## 2. 后台绑定流程

域名字段仅接受合法主机名，端口和协议另填；拒绝用户名密码、路径、换行、shell内容、任意Caddy指令。处理IDN/Punycode时同时显示可读名与ASCII形式，避免同形欺骗；通配域名首期关闭。

状态机：DRAFT → OWNERSHIP_PENDING → DNS_VERIFIED → CERT_PENDING → VALIDATED → ACTIVE；失败保留上个ACTIVE，不把保存成功当公网已可用。

1. Owner登录＋MFA，选用途、主域/别名、目标服务和预期公网IPv4/IPv6/代理模式。
2. 使用一次性随机DNS TXT挑战（含binding_id、有效期）或明确受限HTTP挑战验证控制权。已有域名指向VPS不必然代表提交者有控制权；不能靠随便返回一个200完成。
3. 校验A/AAAA/CNAME与预期入口、证书验证方式和DNS状态，检查无错误AAAA导致一半用户失败。DNS探测仅查域名，不任意抓取内网URL。
4. 生成受限模板配置，验证反代/证书；先配置备用安全管理入口，再执行小范围应用、外部DNS/TLS/Host/WebSocket/播放检查。
5. 激活数据库配置版本和已应用网关版本；不同步则显示待应用。失败回滚本次入口配置，不能回滚业务数据库或删已有证书。

证书由ACME或受控导入管理，私钥不在Bot聊天/代码仓库/普通导出展示。DNS-01令牌仅授目标域DNS记录范围；不把整账户全权限Key交给内容编辑者。自动续期与14天告警、证书链/名称匹配、系统时间、到期恢复都要测。

Caddy可对域名和IP自动启用HTTPS，但公网受信任证书与本地CA行为不同；IP证书是否可由所选CA获取和客户端信任须按版本实测，不武断写“IP永远不能HTTPS”或“自动HTTPS就人人信任”。[Caddy自动HTTPS](https://caddyserver.com/docs/automatic-https)

## 3. IP访问是独立开关

默认`media_ip_access=false`、`account_ip_access=false`、`shop_ip_access=false`；管理入口不因这三个开关开启而公开。IPv4、IPv6分别列明可用地址和证书，不用一个“IP开关”顺手打开所有内部端口。

| 设置 | 访问IP的结果 | 始终保留 |
|---|---|---|
| 关闭（默认） | 不服务该业务，HTTP拒绝或固定最小错误，HTTPS可拒绝握手/默认站点拒绝 | 正常域名服务、受控ACME验证、私网运维 |
| 仅媒体IP入口开启 | 明确配置的IP/端口/TLS服务媒体路由 | 同样鉴权、同播/设备限制；不暴露管理/账户/支付 |
| 账户/商店IP入口开启 | 必须有客户端信任且与IP匹配的有效TLS、正确Cookie/CORS/CSRF和兼容性验证 | 默认仍不开；Mini App继续使用已验证HTTPS域名 |
| 临时应急 | VPN/隧道/管理来源受限、有到期时间 | 不开放无认证公网HTTP后台 |

公网明文HTTP不能接密码、安全码、付款口令、兑换码或令牌；80仅按已知域名安全跳转HTTPS及必要ACME路径处理，未知Host不照抄进Location。启用IP访问不是给用户展示一个可忽略证书错误的地址。未满足TLS条件时保存为未激活草稿，不提供降级明文开关。

关闭“IP入口”仅指没有相应IP虚拟主机；攻击者仍可连接源站IP并提供正确域名的Host/SNI，域名也可解析出IP，不能据此宣称隐藏源站或完成访问认证。如需只允许某可信CDN/VPN访问源站，要有真实源地址网络限制、可信代理配置/证书等独立措施，并覆盖IPv6；首期DNS直达VPS无需假装隐藏源站。

## 4. 反代、TLS和Host边界

公网允许的Host/SNI/端口来自ACTIVE入口白名单；未知域名、IP别名、域名前后缀和不匹配Host不能落到默认业务。业务和网关共同拒绝未授权Host，证书配置不启用任意域名按需签发。HTTP/2连接复用与Host/SNI一致性按固定网关版本验证，避免合法别名误封同时不让管理域落到用户站点。

只信任确切反代/隧道来源的Forwarded/X-Forwarded-*；直接用户伪造X-Forwarded-For不能变管理白名单IP，伪造Proto不能改变安全Cookie/HTTPS要求。上游连接和客户端原始Host/Proto传递要匹配Emby/适配器实际要求，不在公网客户端里散布内网8096/8091端口。[Caddy反代](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy)

账号、后台、商店使用精确Origin允许列表与CSRF；不设置凭据模式下的任意`*`，不把Origin/Referer当唯一身份认证。Emby原生客户端未必发送浏览器Origin，媒体API靠真正用户令牌/准入，不把Web的CORS规则生搬为所有客户端登录拦截。

敏感页面CSP、no-store、Referrer-Policy不泄露订单/票据；外链noopener。日志脱敏query、Authorization、Cookie、红包、兑换码和播放地址。HTTP→HTTPS只用固定受信主域，临时票据默认不在URL，必要一次性引导票据短时、用途绑定且经POST确认不被预取消费。

TLS入口与302/Range/字幕/WebSocket均须实测，证书正确不等于视频链路可用。若使用Cloudflare等代理，按当期产品条款/限制核对视频与直链，不让管理IP规则读取不可信头；源站有TLS且只接受设计的入口。

## 5. 修改、解绑与迁移

换域名先验证新域、证书和样本，再更新服务端地址、Bot菜单/允许域、Mini App来源、登录回调、CORS/CSRF和受控通知链接；不能只改首页文本。别名在过渡期明确保留/跳转，不把含凭据的请求转到任意域名；已发票据按旧origin失效或受控兼容。

解绑先查依赖（活跃主域、后台、Webhook、登录、订单查看、备份目标），唯一管理入口不能直接删。DNS不再控制或域名弃用时撤绑定/回调/证书配置，防旧域被别人接管后仍可登录或收通知。切换不改变用户UID、grant和STRM逻辑身份；媒体域变更会使用户客户端需要更新，通知说明与教程一起发布。

所有域名/IP/管理来源变更有draft、expected_version、MFA、影响预览、配置校验、外部探测、已应用版本和回滚；执行器只用固定模板/白名单字段，不接收任意shell、证书路径、反代上游URL或全权限Docker socket。

## 6. 外部验收矩阵

验证合法域/别名、裸IPv4、裸IPv6、错误Host、伪造Forwarded、SNI/Host不匹配、直连原端口、错误AAAA、过期/不受信证书、未控制域名、Host注入改密链接、恶意CNAME/重定向、域名解绑再被接管。

再测域名切换后的Bot/Mini App登录、付款申请、发码查看、扫码图片、Emby字幕/拖动/302和备份连接。开启/关闭IP入口不能影响VPN救援，不能额外暴露数据库、Emby管理、适配器或备份下载。
