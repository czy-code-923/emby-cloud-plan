# 29 30天自动保号与20天切换冷却最终规则（v8）

2026-11-19用户明确纠正，并确认：**自动续从原到期顺延30天；A只按300可用积分，不设20次签到硬门槛。**本篇及第03/14/15、retention配置为当前规则。旧“20天考核、20活动分/2日达标、周期边界预约”全部作废；旧分析报告和原文仅保留历史。

## 2. 数据与时钟分离

分别保存`playback_end`、免保号区间、`window_id/start/end/status`、本窗签到日期/已结摘要、有效观影时段分配、钱包及版本、`selected_mode/last_selected_mode`、`participation_enabled`、`last_mode_changed_at/next_switch_at`、A授权/撤销epoch/价格上限、`renewal_id/old_end/new_end`、Emby desired/applied版本。

所有时间UTC、显示北京时间。窗口30×24h、实际切换后冷却20×24h、自然日签到去重是三种时钟。换方式不重建窗口，续期不重置冷却；钱包不是本窗专属积分池，消费会真实减少可续余额，但不抹掉已签日期。

## 3. 窗口滚动和一次结算

要续的窗口是`[P－30天,P)`。窗口已开始且未结、当前方式与参与/授权有效、资格/余额或观影充足时：

```text
锁成员、钱包、窗口、mode/end版本；再次检查权限/epoch
A → 写300积分扣款；B → 绑定已核实观影时段（不扣分）
→ 发活动续期grant [P_old,P_old+30天)
→ 唯一标记旧窗已结 → 更新P → 建新窗 [P_old,P_new)
→ 写Emby同步/通知outbox → COMMIT
```

成功较早，新窗尚在未来，面板显示“本窗已结、下一窗尚未开始”。不能余额仍有300就立即再扣，也不能复用刚才30分钟再送一月。唯一键成员＋window_id＋自动续期，不能只用每次生成的新request_id。

例：11月19日00:00开通，P为12月19日00:00；12月9日A够300扣款后P为1月18日00:00，新窗到12月19日才开始。12月10日签到仍赚钱，但重试不会再续。B在11月20日达30分钟，也只续到1月18日，必须等新窗开始再累计其观影。

## 4. A、签到天数和积分卡

每日首次签到继续随机10～20整数等概率、均值15，同日重试返回原奖额。删除旧活动分机制；本窗已签到N天按签到记录时间落入准确窗区间的不同北京时间日期数展示，不虚构固定“2天达标”。30×24h可能跨31个部分本地日期，界面显示N天和起止，不硬写固定分母30。

从零余额只签到不消费，首次够300期望20.4889次，20次够分约51.3997%、22次约98.0433%、30次最低保证。“约20天”只是攒分估计；有旧余额可更早，花分会更晚，余额本已够300则无需再签20天。

选择/恢复A时，预览300费用、30天、旧/新P及自动授权撤回方式。授权有效且窗口可结算时，签到、其他合法钱包变动、窗口开始、切到A、尾窗启用都会触发评估；冻结积分不可花，不欠费负债。A发ACTIVITY_RENEWAL，不是免保号卡。用户可随时撤回未提交扣款授权；价格提高超过同意上限须重新同意。

手动积分月卡仍300/30天、季850/90天、年3000/365天，生成EXEMPT_PLAYBACK，需独立交易确认。A与积分卡花同一钱包，不能各花一遍：手动先提交则旧A候选关闭；A先提交则旧手动预览冲突要求重看。余额充足、重新明确确认的新订单可追加，区别于网络重试。

另行“自动购买免保号积分卡”订阅继续默认关闭，不能借A授权顺便打开；同窗不并行两种自动扣分机制。合法历史积分/管理员调整/游戏奖励可组成钱包，不能伪造本窗签到天数；外部积分接口无直接设置P/发续期的权限，但余额变化可触发用户已授权A。

## 5. B观影与切换进度

窗口有效观影≥1800秒且当前B参与有效，自动免费将P＋30天。相邻可信采样最多90秒、每段至少120秒，多设备重叠取并集，按准确窗口裁剪和分配一次；排除暂停、跳转、预告/浏览/音乐、手工标已看。302缺回报显示盲区，不伪造已达标。

事实可在非所选方式时记录。合法切到B后可以用同一未结窗口已有有效观影；A已结窗时则不能再用旧观看抵第二次续期。跨窗口时段按边界拆分，同一秒不重复记。迟到事件默认24小时内按真实发生时间处理；采集故障暂停受影响冻结并按事故延期，不强制购买。

## 6. 20天实际变更冷却

首次选A/B或真正A→B/B→A时记录now与`next_switch_at=now+20天`。解锁后不换就一直保留权利，只有下一次实际变更才再次冷却；不因“错过某20天档期”失效，也不累计多张可瞬切券。

| 情景 | 结果 |
|---|---|
| D0首次A，D10请求B | next_switch_at仍D20，拒绝提前换，不改变P |
| D20解锁但不换，D35才A→B | D35即时生效，下一次D55；继续保留此前A结算 |
| D36重复B | 幂等，仍D55，不重置成D56 |
| D55没换，D80再B→A | D80立即换，下次D100；不能连换两次 |
| 自动续期、买卡、免保号、恢复或迁移 | 保留原next_switch_at |
| 关参与/撤A授权再启原方式 | 不算实际A/B变更，也不允许绕过换另一方式的冷却 |

解锁变更立即对当前未结窗口重评，不预约下期，不改变窗口/P/钱包。切换和结算锁相同状态，mode_version不符的旧A任务不能在切B后扣款。

## 7. 免保号最后不足30天

1. 新卡/购买/管理员免保号默认参与OFF；余额1000也不扣，正常签到入钱包。
2. 严格剩余不足30天才显示自愿启用A/B，A明确确认自动费用；无选择仍正常使用至原P，无活动欠账。
3. 启用沿用原最后30天窗口和P，不取消剩余豁免。条件满足可先P＋30天，原豁免仍在，新增段为活动保号，从旧P开始。
4. 历史偏好仅作提示，不等于尾窗授权。恢复相同方式不重置冷却；更换另一方式仍检查原next_switch_at；永久免保号无尾窗。
5. 已续后总剩余≥30天，当前免保号者先收起尾窗选择，记录方式/授权/冷却，下一活动段到来后继续。若另买/兑卡使持续免保号延长，则暂停尾窗参与、关闭旧未结候选，未来不足30天再明确启用。
6. 到期没参与不白送30天、不默认A追扣300；按普通到期/资料保留处理。

尾窗可使用窗内启用前已经认证的有效观影；不能用窗外总历史。签到日期也显示本窗真实数据，钱包余额不限于这些日期赚到的分。

## 8. 卡券顺延、剩余时长与退款

统一保留未用播放，卡券/管理员时长追加到当前连续P。免保号卡立即保护到新终点：活动还剩10天，兑30天卡后可用40天，其中原10天转免活动是明示赠送overlay，卡本身新增仍30天；不把原活动grant改成付款事实。

保存原段、新增卡段、赠送overlay、窗口、价格/效果/政策快照，退款撤对应来源再重算，保护后来独立grant/真实核销。不追罚有效豁免期间未签到/观影，不简单“当前到期减30天”。首期继续第16篇全单人工核准/实收实退/冻结码与核销互斥规则。

## 9. 到期、救济与故障

没续到P时普通到期冻结播放，保留本人身份/客服/资料至少30天，不默认删用户。已选活动参与者保留每失败窗一次7天救济播放grant，独立标记，不刷新P/窗口/冷却；无尾窗参与的免保号到期不凭此白送一月。

到期后A补救必须明确确认，不在后来攒够分时后台追扣；救济成功仍按失败窗旧P＋30天，已使用的救济时间包括在内。B救济时段单独rescue归属，不同时给下一窗。系统故障导致迟提交的资格按可追溯时间/事故记录处理。

扣款、grant、窗口、P、outbox同事务。Emby使用单调desired/applied版本；失败显示“续期已记账、Emby同步中”，只重试同步，不再扣300。通知失败只补通知，旧任务不准覆盖新P。
