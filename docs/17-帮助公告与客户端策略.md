# 17 用户帮助、公告与客户端策略（v5）

## 1. 用户能在哪里找到

保留五个底部入口，首页展示置顶公告/维护条；“我的”提供使用帮助、客户端兼容与禁用清单、全部公告、订单、工单与隐私说明。原生Bot增加`/guide`、`/announcements`、`/clients`，`/help`聚合；未注册访客可读公开帮助，不暴露受限服务器地址。

公告状态和业务状态分别显示：全服维护不等于用户封禁，人工核款待办不等于付款失败。交易、签到和码核销结果不被公告横幅遮挡。公告关闭只隐藏内容，不自动关闭注册/播放；维护开关也不能仅靠发一条公告实现。

## 2. 帮助中心结构

| 分类 | 必须覆盖 |
|---|---|
| 开始使用 | 注册/绑定、设置密码、安全码、保存恢复码、服务地址/端口、手机/电视/电脑登录 |
| 播放 | 直播放、字幕/多音轨、拖动、编码/HDR兼容、2GB不支持实时转码的限制 |
| 客户端 | 推荐/已测版本、限制/禁用原因、替代方案、更新日期；客户端自身许可单独说明 |
| 保号与积分 | 签到/观影20天、模式预约、钱包/活动分区别、随机概率、免保号与期满回退 |
| 购买与兑换 | 独立网页人工收款说明、人工核对时限、单次码、核销起算、价格/限额、退款 |
| 故障处理 | 线路不可达、域名/TLS、网盘风控、统计延迟、账号冻结、码已用/同步中 |
| 账户与隐私 | 解绑/改密、恢复流程、本人导出、消息通知、数据保留、支持渠道 |

每篇有稳定content_id、标题/分类、摘要、正文、适用入口/角色/系统/版本、公开级别、草稿/发布状态、有效期、更新时间、责任人。FAQ可搜索、分页与锚点，不在每次打开帮助时读取全库海报。

后台提供新建/编辑、预览、版本比较、定时发布/撤回、置顶和回滚；正式文档与草稿分离，不能边编辑边改变线上说明。收款帮助应关联当前已发布规则版本，不把已过期收款码截图留在教程中；地址引用走线路变量，按读者资格解析，不把内部地址硬写公开正文。

## 3. 公告的发布和阅读

公告类型：维护、客户端政策、功能更新、规则/价格变更、故障恢复、一般通知。字段包括等级、受众、开始/结束、置顶、是否需确认、关联规则版本、链接与渠道。允许全体/已注册/某套餐/节点/受影响用户筛选，用户只能看到自身范围。

默认首页最多3条摘要，置顶不等于群发；弹窗只用于必要变更并记录(user,announcement_id,version)确认，不能每次刷新重弹。已读与“已同意条款”分开，送达不等于用户同意。

严格规则和价格变更写生效时间、影响及过渡，不回溯修改已付款快照；紧急安全策略可即时生效，但记录原因和补救。故障恢复公告不擅自重开销售；需要对应开关明确发布。

Bot/频道推送为可选发布动作，先预览受众数量；使用outbox去重、节流、静默与失败恢复。频道不包含个人订单/口令/码/观看史；误发撤回不能宣称已删除所有用户副本。后台编辑公告属于内容权限，不应附带修改角色/域名/支付收款人权限。

## 4. 客户端限制分层

不在方案里凭空把某个市售客户端列入黑名单。管理员按实际测试/明确违规维护条目：产品标识、平台、版本范围、匹配特征、级别、原因、替代建议、生效/失效、关联证据与例外。

| 级别 | 用户界面 | 后端行为 |
|---|---|---|
| TESTED / RECOMMENDED | 已测条件与日期 | 正常处理，不保证所有版本 |
| UNSUPPORTED | 未测/不兼容与替代建议 | 默认提示，不凭未知UA全封 |
| WARN | 风险提示 | 记录并提示，可继续 |
| DENY_NEW_PLAY | 明确禁用原因/版本/申诉 | 在已覆盖的播放准入入口拒绝新播放 |
| BLOCK_DOWNLOAD | 不支持下载 | 所有已确认下载/原文件路径鉴权拒绝，不只隐藏按钮 |

客户端名称/UA/DeviceId可被伪造，只能作策略线索，不能宣传为绝对防盗。正式开启DENY_NEW_PLAY要先证明Emby、网关和不同播放路径可一致执行；原生Emby的实际可配置项以部署版本为准。未做到强制执行，面板必须写“使用规则/提示，尚非硬封锁”。

至少测试登录、PlaybackInfo、直链签发、直接流、下载、HLS/DASH、字幕、浏览器、电视与重命名客户端；避免误封系统健康探针/Emby内部取源。未识别客户端默认允许受控鉴权并记录；Owner可改为未知拒绝，但须给恢复入口和兼容性影响预览。

个人例外只覆盖客户端政策的明确一项、有期限与审计，不绕过账号安全封禁或总同播。买白名单默认无此例外；已有上游302链接通常不能立即撤回，策略只保证覆盖入口之后的新授权受限。

## 5. 内容编辑安全

正文使用受限Markdown，禁止任意HTML/JS/iframe/脚本组件；服务端净化，链接只允许http/https并检查目标，禁止javascript/data伪协议。图像默认上传受控静态区，不由服务器任意抓取用户URL。客户端政策匹配先用结构化名称/版本/有限前缀；不让编辑者注入任意耗时正则。

图片做类型/尺寸/像素/文件大小校验并重新编码，移除EXIF；不直接执行SVG/HTML，不开放上传目录浏览。外链标记并避免把身份/订单参数带给第三方；CSP限制来源。手机弹窗可关闭、键盘/读屏可操作，不能通过“必须读公告”阻断安全码恢复或付款售后。

内容、客户端策略和公告都需要后端对象权限、expected_version、审计、回滚；批量群发需预览，不因拿到内容编辑权限就能发送任意私信。参考[OWASP上传安全](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html)。

## 6. 验收

草稿不泄露、定时/跨时区发布正确、撤回不删除审计；访客看不到付费地址、用户看不到他人定向公告；恶意链接/图片/Markdown不执行；禁止客户端公告与实际准入状态分别可见；手机320px、长标题、空列表、断网缓存和屏蔽Bot均有可用入口。
